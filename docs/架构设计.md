# CodeMind 教辅平台 · 架构设计

> 更新时间：2026-10-27
> 范围：以当前代码说明后端结构；本轮补齐非学生端接口，不新增前端页面。
> 部署状态：本轮 5 项迁移已于 2026-10-27 在本地业务库备份后应用并校验；生产环境须独立确认。

## 一、技术栈与应用边界

CodeMind 使用 Django、Django REST Framework、django-axes、openpyxl、django-q2 和 SQLite。认证使用 Django Session；模板用于开发预览，业务接入以 API 为主。数据库切换须重新验证约束与并发行为，不预设必须使用 MySQL。

```text
前端 / 开发预览模板
        │ HTTP + Session + CSRF
        ▼
Django 项目 codemind
   ├── users       认证、身份、权限、个人资料、教务账号维护
   ├── academics   学院专业、行政班、课程、教学班、学籍、学期、审计
   ├── teaching    题库、作业、提交、教师看板、评阅、资料和通知
   ├── course_team 课程组知识、文档、章节、共享资料和教师只读接口
   └── tasks       后台导入、判题任务执行及恢复调度
        │
        ├── SQLite：业务记录、Django Q2 ORM broker
        ├── 私有目录：班级资料、课程资料、临时导入源文件
        └── go-judge：编译与隔离执行
```

`tasks` 默认集群 `codemind` 执行教务导入，`long` 集群执行判题；Agent 扩展默认未启用。两个集群及调度进程均须纳入部署运维，生产验收见 [OJ验收清单.md](OJ验收清单.md)。

## 二、数据模型

### 2.1 账号、学籍与教学组织

```text
User ── SchoolIdentity ── StudentProfile ── ClassMembership ── AdminClass
             │                                               │
             └── TeacherProfile                              Major ── Department

Course ── CourseCollege ── TeachingClass
              │                 ├── admin_classes：组成行政班
              ├── leader        └── teachers：任课教师
              ├── teachers：教师池
              └── admin_classes：候选行政班

AcademicTerm.code ← TeachingClass.term
TeachingClass ── TeachingClassRecord：结课名单及归档成绩
AuditEvent：管理动作与显式挑选的变更字段
```

| 模型 | 责任与约束 |
|---|---|
| `users.User` | 统一登录账号，`username` 唯一；角色使用 Group，密码哈希存储，`must_change_password` 控制首次改密 |
| `users.SchoolIdentity` | 学工号绑定；同校同类型学工号唯一，同用户同校同类型唯一 |
| `users.StudentProfile` | 专业、入学年份、在读/休学/毕业/退学状态 |
| `users.TeacherProfile` | 所属学院与职称；学院是档案属性，任课权限由教学班教师关系决定 |
| `academics.Department` / `Major` | 学院与专业，含编码和启用状态；专业挂学院 |
| `academics.AdminClass` | 学籍班级，挂专业，含入学年份、编码和启用状态 |
| `academics.ClassMembership` | 入班/离班历史；条件唯一约束保证同一学生最多一条当前关系，检查约束保证离班日期不早于入班日期 |
| `academics.Course` / `CourseCollege` | 课程含启用状态；课程×学院承载组长、教师池和候选行政班 |
| `academics.TeachingClass` | 同课程、同学期组建的授课单位；至少一个组成行政班，组成班级同学院、来自候选池且不重复组班 |
| `academics.AcademicTerm` | 学期编码、起止日期、当前标志及开放/关闭/归档状态；至多一个开放的当前学期 |
| `academics.TeachingClassRecord` | 一教学班一记录，关闭时冻结名单，归档时冻结逐作业成绩 |
| `academics.AuditEvent` | 操作人、时间、对象类型及编号、动作和变更前后数据；删除操作人后保留用户名快照 |

`TeachingClass.term` 保留字符串字段兼容既有接口，公开组班接口要求编码已在 `AcademicTerm` 登记。完整字段与迁移边界见 [数据库表重构设计.md](数据库表重构设计.md)。

### 2.2 教学与课程组数据

| 模型组 | 责任 |
|---|---|
| `Problem`、`Homework`、`HomeworkProblem` | 公共/个人题库、作业组卷及作业题面/测试数据快照 |
| `Submission`、`JudgeTask`、`AgentTutorReport` | 提交、受理时判题快照、可恢复执行状态及预留 Agent 报告 |
| `SubmissionReview`、`TeachingMaterial` | 教师批语与私有班级资料 |
| `ClassNotice`、`NoticeRead`、`HomeworkReminder`、`HomeworkAnswer` | 通知、首次阅读、站内提醒、教师手写参考答案 |
| `course_team.CourseKnowledge` | 手工知识或原始文档、解析正文、ready/failed 状态与错误摘要 |
| `course_team.CourseMaterial`、`MaterialTeachingClass` | 私有共享资料及指定教学班可见范围 |
| `course_team.CourseChapter` | 课程×学院内章节顺序及知识、资料关联 |
| `tasks.AsyncTask` | 既有题库导入等任务历史 |
| `tasks.OfficeImportJob` | 教务 XLSX 导入批次、进度、物理行游标、错误及执行轮次 |

私有文件与数据库分别保存：数据库存随机存储标识和展示元数据，文件保存于 `PRIVATE_MATERIAL_ROOT`。接口先授权再打开附件，不提供公开物理路径。数据库备份不能替代私有文件备份。

## 三、权限与访问控制

权限体系保留四分组和 22 个显式权限码：教务 5 项、课程组 3 项、教师 9 项、学生 4 项，加四组共有的 `profile:edit`。Django 自动生成的模型权限与这些业务权限码分开管理。

| 入口 | 功能权限与对象范围 |
|---|---|
| 教务基础维护 | 学院/专业/课程/学期使用 `course:manage`；行政班、普通账号、学籍和审计使用 `class:manage` |
| 任课与组长设置 | 分别要求 `class:assign_teacher`、`user:assign_role`，组班分配要求 `course:assign_class` |
| 课程组写入 | 对应知识、共享资料或章节权限码，加 `CourseCollege.leader` 任职校验；拥有课程组分组不等于可管理所有课程 |
| 教师业务 | 功能权限加任教关系；共享课程资源只读入口要求教师组及对应课程×学院任课范围 |
| 学生既有业务 | 当前学生身份、档案和当前成员关系推导教学班；仅完成教师布置的作业 |
| 系统管理员 | 公共题库独占维护；高权限账号维护和他人密码重置 |

标准请求依次校验认证、功能权限、对象范围、状态和请求字段。越界对象通常返回与不存在对象相同的 404；功能权限不足返回 403。`PermRequired` 要求显式有效权限声明，系统检查验证权限注册、映射、分组定义和数据库实际分配一致。完整规则见 [用户权限设计.md](用户权限设计.md)。

## 四、后端业务流程

### 4.1 学籍与组织维护

教务可手工维护学院、专业、课程及行政班，并启用或停用；停用保留既有数据，阻止受影响的新建组织、组班、入班和导入操作。存在关联数据时限制专业所属学院、行政班专业/入学年份等结构变更，历史数据或受保护资源不能通过级联删除绕过。

普通转班仅限同专业、同入学年份，日期由服务端按本地当日确定。学籍异动可显式变更专业与入学年份：先结束原成员关系，指定新班时再验证新专业、年份和启用状态。休学、毕业、退学结束当前关系，保留账号、历史成员和提交；恢复在读不自动回班。学号和登录账号不随异动重写。

教务账号接口维护普通教师/学生资料和启停状态；带高权限的目标仅系统管理员可管理。密码重置校验 Django 密码策略、置首次改密标志并使旧会话失效，不返回密码或哈希。

### 4.2 学期与历史保留

| 状态 | 允许行为 | 历史处理 |
|---|---|---|
| `open` 开放 | 组班、分配任课、发布作业和正常教学写入 | 使用当前成员名单 |
| `closed` 关闭 | 查询、教师评阅和参考答案收尾 | 冻结教学班名单，后续转班/毕业不改结课名单 |
| `archived` 归档 | 教学班历史查询、成绩与导出 | 冻结逐作业成绩；教学班写入只读 |

关闭前必须所有作业已截止；归档必须先关闭，且无排队或判题中的提交。关闭会保留有历史提交的离班学生，成绩逐题取最高有效终态得分。教学写入先校验并锁定学期，再处理业务对象；成员服务与结课使用共同的学期锁。

学期约束针对教学班数据；可复用的课程组知识和章节继续按课程组服务管理，共享资料指定班级范围须符合对应学期限制。学期、名单和成绩规则详见 [教学班级设计.md](教学班级设计.md)。

### 4.3 后台导入与审计

教务 XLSX 原有同步入口保留，新增批次接口用于后台导入。上传预检限制文件大小、解压量、列和数据行数；默认队列每段最多处理 100 行或运行 60 秒，逐行事务将业务写入与批次游标同时提交，再续投剩余部分。

批次可查询进度、逐行结果及下载错误 CSV。重复投递和恢复使用批次轮次、状态和物理行游标防重；失败或部分成功批次通过重新上传文件显式重试。已有账号不会被覆盖密码。终态清理原始表格，超时调度回收失联任务及孤立文件；队列参数不含初始密码，原始表格无下载接口。

`AuditEvent` 随管理服务事务记录操作人、对象、动作与显式挑选的前后数据；业务回滚时审计也回滚。既有教务组织接口和 Django 后台角色、账号、组织维护也接入业务审计，同时保留后台原生 `LogEntry`。密码、文件正文、隐藏测试点等不进入审计。批次历史与审计查询分别使用导入接口和教务审计接口。

### 4.4 教学与课程资源

学生不允许公共题库自由练习，教师个人题只在已布置作业上下文对对应学生开放。作业题目和判题数据使用冻结快照，隐藏测试点、SPJ 和 Agent 自测代码不下发。

教师可维护班级通知、私有资料、手写参考答案，查看看板和代码、评阅及导出成绩。参考答案截止后手动公开；首次公开后不能再延期或换题。提醒仅生成站内记录，针对未交齐题目的学生，同作业同学生一小时去重。

课程组知识支持手工维护、批量导入、同步文档解析、失败摘要和重新解析；文档解析支持 UTF-8 TXT/Markdown/CSV/JSON 及标准 DOCX，不调用外部 AI/OCR。章节关联须属于同一课程×学院。共享资料面向本课程任课教师或指定教学班的任课教师；本轮提供教师只读接口，不新增学生侧课程组资源入口。

## 五、接口地图

| 前缀 | 用途 |
|---|---|
| `/api/auth/` | 登录、登出、当前权限、改密和个人资料 |
| `/api/office/` | 新增基础维护、账号、学期和审计 |
| `/api/import-jobs/` | 教务后台导入批次、进度、错误下载及重新上传重试 |
| `/api/students/` | 教务学生档案、成员历史、转退班和学籍维护 |
| `/api/courses/`、`/api/teaching-classes/` 等 | 保留既有教务组织管理接口及返回契约 |
| `/api/teacher/` | 教师班级、题库、作业、看板、评阅、资料及沟通功能 |
| `/api/course-team/` | 课程组管理及其 `teacher/` 子路径下的教师只读资源 |
| `/api/admin/` | 系统管理员公共题库导入 |
| `/api/homeworks/`、`/api/problems/`、`/api/submissions/` 等 | 既有学生作业与提交接口 |

本轮新参数、响应和错误语义统一见 [非学生端后端接口.md](非学生端后端接口.md)；既有接口见 [API设计文档.md](API设计文档.md)。`/office/`、`/teacher/`、`/student/` 的模板仍为已有开发预览，新增后端功能未配套新增页面。

## 六、迁移与交付边界

本地上一阶段已应用 `teaching.0006_teacher_backend` 和 `teaching.0007_teacher_communication`。**本轮以下 5 项迁移已于 2026-10-27 经用户单独授权在本地业务库应用**，原有 40 张业务表按原列计算的逐行指纹未变：

| 应用 | 新迁移 | 影响 |
|---|---|---|
| `academics` | `0011`、`0012` | 课程/行政班启用字段；学期、冻结记录、审计表；登记既有字符串学期并延续当前学期配置 |
| `tasks` | `0004`、`0005` | 教务导入批次表与恢复调度 |
| `course_team` | `0001` | 课程知识、共享资料、指定班关联及章节表 |

本地备份为 `db.sqlite3.backup-20261027-150652-227043`，新增 10 张表、登记 1 个学期及默认集群每分钟回收排程，完整性和外键检查通过；详见 [API设计文档](API设计文档.md) 3.10。本地迁移不代表生产库已升级或默认 worker 已实机验收。部署须另行备份、检查计划、应用迁移并验证数据和队列。

剩余业务决策为正式学号/工号格式、学校组织编码及实际学期日历。旧 8 位学号自动分班规则保留为占位；格式未定时使用指定班级导入。学生画像、教师 AI 扩展、前端接入及生产运维验收分别规划，不计入本轮已补齐接口。
