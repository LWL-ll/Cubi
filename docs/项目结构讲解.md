# CodeMind 教辅平台 · 项目结构讲解

> 更新时间：2026-10-27。面向首次接手项目的开发者，以当前代码为准。
> 教务、教师、课程组及学生端后端清单已落实，不新增前端页面；非学生端阶段本地业务库迁移已验证，学生端阶段无新增迁移，生产环境独立验收。

## 一、项目与目录

CodeMind 是教师布置作业、学生提交代码、系统隔离判题的教辅平台，包含教务组织与学籍管理、课程组资源管理。业务主线是 Django + DRF API，认证使用 Session 和 CSRF；已有模板用于开发预览。当前数据库为 SQLite，队列使用 django-q2 的 ORM broker，不要求先安装 Redis。

```text
codemind/
├── manage.py              Django 命令入口
├── codemind/              全局配置与总路由
├── users/                 认证、账号、身份、权限、个人资料
├── academics/             教务组织、成员、学籍、学期和审计
├── teaching/              题库、作业、提交、教师业务与 OJ 接口
├── course_team/           课程组知识、文档、章节和共享资料
├── tasks/                 教务导入 worker、判题 worker 与恢复任务
├── templates/             已有登录、教务、教师、学生与后台预览模板
├── docs/                  架构、接口、业务规则与验收文档
├── deploy/                判题沙箱部署约定和 Nginx 配置参考
├── scripts/               沙箱探针及隔离队列验收脚本
├── private_uploads/       私有文件与导入临时源文件，运行产物不入库
└── db.sqlite3             本地业务数据库，不入库
```

数据库保存记录和文件标识，私有资料正文不在数据库中。备份和恢复须同时考虑数据库与私有文件。

## 二、应用分工与关键文件

### 2.1 codemind：配置和路由

| 文件 | 责任 |
|---|---|
| `settings.py` | 注册五个业务应用、DRF、axes、Q2；配置 Session、SQLite、私有存储、OJ 和各队列集群 |
| `urls.py` | 挂载认证、教务、教师、学生、课程组和管理员 API，以及已有预览页面 |
| `wsgi.py` / `asgi.py` | 服务入口；生产启动与进程守护另行配置 |

默认 Q2 集群 `codemind` 执行教务导入，`long` 执行判题，`agent` 为默认关闭的 Agent 扩展接入点。Web 和 worker 需要分别运行，见 [异步任务设计.md](异步任务设计.md)。

### 2.2 users：账号与权限

| 文件 | 责任 |
|---|---|
| `models.py` | `User`、`SchoolIdentity`、`StudentProfile`、`TeacherProfile`；22 个显式业务权限声明 |
| `permissions.py` / `checks.py` | 权限码、四分组、功能权限和入口类；检查注册、映射、数据库分配及 API 声明 |
| `api.py` / `urls.py` | CSRF 引导、登录及 token 轮换、登出、当前用户、本人改密和个人资料接口 |
| `profile_service.py` | 本人资料白名单，不能自助改角色、身份或学校归属 |
| `account_api.py` / `account_service.py` | 教务普通教师/学生账号维护；高权限目标及他人密码重置仅系统管理员 |
| `middleware.py` | 首次登录强制改密，对页面和 API 同时生效 |
| `admin.py` | 系统管理员的用户、组、身份及档案维护；审计和后台改密处理 |
| `tests*.py` / `migrations/` | 认证、权限、账号回归；身份、分组和权限数据迁移 |

`SchoolIdentity` 绑定学工号，`User` 管登录。学生业务读取最早的学生身份和对应资料，缺失资料时不自动改选后续身份。角色使用 Django Group，没有新增 `role` 字段。

### 2.3 academics：教务与历史

| 文件 | 责任 |
|---|---|
| `models.py` | 学院、专业、行政班、成员、课程、课程×学院、教学班、学期、冻结记录和审计事件 |
| `api.py` / `serializers.py` | 保留的教务组织接口与返回格式；动作权限和组织变更审计 |
| `base_api.py` / `base_service.py` | 学院/专业/课程/行政班 CRUD、启停及学籍异动服务 |
| `student_api.py` | 教务学生检索、详情、成员历史、当日转退班及学籍维护；不是学生自助 API |
| `term_api.py` / `term_service.py` | 当前学期、关闭、归档、写入限制、冻结名单与成绩；只读审计查询 |
| `services.py` / `signals.py` | 一人一当前班、组班与候选池规则、历史删除保护、M2M 正反向约束 |
| `audit_service.py` / `audit_admin.py` | 显式白名单审计、事务一致性与 Django 后台业务审计 |
| `views.py` | 已有教务预览页面及共享 XLSX 解析、逐行导入逻辑 |
| `student_no.py` | 旧 8 位占位规则：4 位入学年、2 位专业码、2 位班序；正式格式仍未定 |
| `api_urls.py` / `urls.py` | `/api/` 下教务接口与 `/office/` 预览页面路由 |
| `admin.py` | 后台组织管理、教学班组成表单、审计接入 |
| `tests*.py` / `migrations/` | 导入、组织、成员、学籍、学期、审计及历史模型迁移回归 |

学生经在读 `StudentProfile → ClassMembership → AdminClass → TeachingClass` 推导当前教学班；教师按 `TeachingClass.teachers` 判断任课。`TeachingClassRecord` 提供结课名单和归档成绩；学生当前内容资格另与冻结名单相交，本人历史摘要资格单独计算，不能仅凭快照恢复题面或下载。

### 2.4 teaching：教学与 OJ

| 文件 | 责任 |
|---|---|
| `models.py` | 题目、作业、冻结题目、提交、判题任务、评阅、班级资料、通知、阅读、提醒、答案及 Agent 报告 |
| `helpers.py` | 教师任教和学生当前内容范围，跨范围对象统一 404 |
| `student_scope.py` | 首个身份、在读在班、冻结名单及本人历史摘要范围；每次请求重算 |
| `student_service.py` | 本人上下文、课程、作业筛选、成绩反馈、通知资料、首页及画像 |
| `student_api.py` / `student_api_urls.py` | `/api/student/` 聚合接口、权限、查询字段与分页 |
| `problem_markdown.py` / `problem_service.py` | 录题解析、题库读写、revision 及保密字段过滤 |
| `problem_import.py` | 公共/个人题库 ZIP 同步导入、去重覆盖和 `AsyncTask` 历史 |
| `homework_service.py` | 组卷、选题权限、作业题目快照及已有提交/答案公开后的锁定规则 |
| `submission_service.py` | 准入校验、学期/作业限制、限流、判题快照与提交后入队 |
| `judge.py` | go-judge 调用、C/Python 运行、比对、SPJ 及资源限制 |
| `teacher_service.py` | 名单、看板、提交查看、批语、成绩聚合与 XLSX 导出 |
| `material_service.py` | 私有班级资料验证、保存、授权下载和文件生命周期 |
| `shared_material_service.py` / `shared_material_api.py` | 教师从共享资料/章节选材，核验目标班范围并创建独立班级资料副本 |
| `submission_titles.py` | 提交列表及详情读取作业冻结题名，避免实时改题改变历史显示 |
| `communication_service.py` / `answer_service.py` | 通知、阅读、站内提醒、手写参考答案及公开规则 |
| `api.py` / `communication_api.py` / `serializers.py` | 教师和既有学生接口、字段白名单 |
| `admin.py` / `admin_api.py` | 超级用户独占的公共题库维护与导入 |
| `agent_service.py` | Agent 讲题预留入口；默认关闭，不代表已接入外部模型 |
| `*_urls.py` / `views.py` | API 分发与已有预览页面 |
| `tests*.py` / `migrations/` | 对象权限、教学功能、判题保密、任务恢复与迁移回归 |

学生只能提交教师布置的作业，不能自由练习公共题库。教师个人题只在布置作业上下文对相应学生开放；题面和提交接口不下发隐藏测试、SPJ 或判题快照。

### 2.5 course_team：课程组资源

| 文件 | 责任 |
|---|---|
| `models.py` | `CourseKnowledge`、`CourseMaterial`、`MaterialTeachingClass`、`CourseChapter` |
| `services.py` | 功能权限与负责人范围、任课教师读取、同课程关联、章节排序和资料可见范围 |
| `storage.py` | 私有文件验证与保存、UTF-8/标准 DOCX 同步解析、下载和清理 |
| `api.py` / `serializers.py` / `urls.py` | `/api/course-team/` 管理接口及 `teacher/` 子路径只读接口 |
| `tests*.py` / `migrations/` | 越权、格式、关联、文件、归档范围和并发回归；初始模型迁移 |

负责人按具体 `CourseCollege.leader` 管理资源，教师需有对应任课关系。共享资料可以全课程任课教师可见，或限定指定教学班的任课教师。学生不直接访问源库；教师通过 `teaching.shared_material_service` 选材下发独立班级副本。

### 2.6 tasks：后台执行

| 文件 | 责任 |
|---|---|
| `models.py` | `AsyncTask` 既有任务历史及 `OfficeImportJob` 教务导入批次 |
| `import_api.py` / `import_urls.py` | `/api/import-jobs/` 的受理、历史、进度、错误下载和重传重试 |
| `import_service.py` | 导入权限、私有源、轮次、入队、超时回收和孤立文件清理 |
| `tasks_import.py` | 每段最多 100 个有效行或约 60 秒，行事务同步业务写入与游标，再续投 |
| `tasks_judge.py` | 判题租约领取、进度、终态、补投与失联回收 |
| `tasks_agent.py` | Agent 扩展任务入口，默认不启用 |
| `tests*.py` / `migrations/` | 防重、撤权、重试、源清理、判题恢复及调度迁移 |

## 三、接口入口速查

| 前缀 | 主要用途 |
|---|---|
| `/api/auth/` | 认证和本人资料 |
| `/api/office/` | 基础、账号、学期和审计 |
| `/api/students/` | 教务学生与学籍管理 |
| `/api/courses/`、`/api/teaching-classes/` 等 | 既有组织接口 |

| `/api/homeworks/`、`/api/problems/`、`/api/submissions/` 等 | 既有学生作业与提交接口 |

新增接口详细字段见 [非学生端后端接口.md](非学生端后端接口.md)、[学生端接口.md](学生端接口.md)，既有接口见 [API设计文档.md](API设计文档.md)。

## 四、修改与验证入口

| 任务 | 修改位置与验证重点 |
|---|---|
| 调整权限点 | `User.Meta.permissions`、`PERM_CODES`、`GROUP_PERMISSIONS` 和迁移同时同步；系统检查与权限回归 |
| 增加教务功能 | 对应 `academics`/`users` API 和服务；字段、目标范围、状态、事务和审计 |
| 改成员/学籍 | 复用入班、转退班和学籍服务；一人一班、当前访问范围及结课名单冻结 |
| 改学生聚合 | `student_scope` 与 `student_service`；本人范围、冻结成绩、旧接口兼容、逐项撤权及查询数 |
| 改学期 | `term_service.py` 及所有受影响教学写入口；关闭、归档、在途判题和历史读取 |
| 改课程组 | `course_team` 服务和接口；负责人/任课范围、同课程关联、可见性和文件生命周期 |
| 改导入 | `academics.views` 行逻辑 + `tasks` 生命周期；逐行原子、防重、撤权与重试 |
| 改数据表 | 模型和迁移；先用测试库验证，业务库迁移另行授权、备份和校验 |
| 改正式学号格式 | 先取得学校规则，再改解析、相关校验和回归；不要猜格式或改写已有账号 |

具体测试结果在交付说明中记录，文件地图不固化用例总数。Git 协作规则统一见 [AGENTS.md 的版本管理约定](../AGENTS.md#版本管理)。
