# CodeMind 教辅平台 · 教学班级设计

> 更新时间：2026-10-27
> 范围：行政班、教学班、成员历史、学期关闭和归档的当前后端规则。
> 本轮学期与冻结记录迁移文件已生成，尚未应用到业务库。

## 一、行政班与教学班

| 概念 | 性质 | 组成与用途 |
|---|---|---|
| `AdminClass` 行政班 | 学籍单位 | 所属专业与入学年份确定；学生经 `ClassMembership` 入班，同一学生最多一个当前班 |
| `TeachingClass` 教学班 | 授课单位 | 在一个课程×学院、一个学期内，由 1 至 N 个行政班组成；教师、作业、通知和班级资料挂在此处 |
| `CourseCollege` 课程×学院 | 课程管理范围 | 保存组长、教师池与候选行政班；课程组资源也归此对象 |

一个行政班可以整班单独授课，也可以与同学院的其他行政班合班。行政班不拆分；同课程同学期不能将同一行政班重复编入两个教学班。

## 二、模型和归属推导

```text
User ── SchoolIdentity(student) ── StudentProfile
                                      │
                                      ▼
                               ClassMembership
                            joined_at / left_at
                                      │
                                      ▼
                                  AdminClass ── Major ── Department
                                      ▲
                                      │ admin_classes
Course ── CourseCollege ── TeachingClass ── teachers(User)
                               │ term 字符串引用 AcademicTerm.code
                               ├── Homework / ClassNotice / TeachingMaterial
                               └── TeachingClassRecord
```

`TeachingClass` 字段使用代码中的 snake_case：`name`、`term`、`course_college`、`admin_classes`、`teachers`。`(course_college, term, name)` 唯一。`term` 保持字符串以兼容既有接口；公开组班前须登记相应 `AcademicTerm`。

学生访问范围仍由最早的学生身份、对应档案、当前成员关系和行政班组成关系推导；最早身份缺档案时不改选后续身份。学生不直接保存教学班成员表。教师访问范围由 `TeachingClass.teachers` 决定，教师档案所属学院不授予任课权限。

关闭后的 `TeachingClassRecord.roster` 是教师历史查询名单，不作为学生访问其他班级的授权凭据。

## 三、组织与删除约束

| 编号 | 约束 |
|---|---|
| C1 | 所有组成行政班须经专业归属同一学院，并在对应课程×学院候选池中 |
| C2 | 同课程同学期，一个行政班只组成一个教学班；不同课程可分别组班 |
| C3 | 任课分配接口验证课程教师池；工号添加会先加入本课程教师池 |
| C4 | 同一课程×学院、同一学期内教学班名唯一 |
| C5 | 已有作业、班级资料、通知、结课冻结记录或课程组指定资料关联的教学班受保护，不能通过解散或解除课程×学院删除历史 |
| C6 | 正向、反向移除或清空组成关系不能移除最后一个行政班；后台替换唯一组成班先加入新班再移除旧班 |
| C7 | 正在组成教学班的行政班不能移出对应候选池 |
| C8 | 行政班有任何当前或历史成员，或仍组成教学班时禁止硬删除；新基础维护接口也保护候选池关联 |
| C9 | 停用的课程、学院、专业或行政班不能用于相应新组班、入班和导入；历史关系保留 |
| C10 | 行政班已有成员或课程关联时，不能直接更改专业、入学年份；已有班级或学籍的专业不能直接改所属学院 |
| C11 | 关闭学期禁止新增教学写入、组成和任课变更，只允许评阅与参考答案收尾 |
| C12 | 归档学期教学班数据只读；关联基础名称、编码等历史字段不能经新维护接口改写，单独启停状态可维护 |

核心约束通过 `academics/services.py`、`term_service.py`、模型保存和 M2M 信号共同落实；使用数据库条件唯一约束保证当前成员唯一，日期检查保证 `left_at >= joined_at`。不要直接改中间表或以批量 SQL 绕过服务。

## 四、成员和学籍异动

| 操作 | 当前成员关系 | 其他数据 |
|---|---|---|
| 普通转班 | 按本地当日关闭旧关系、建立新关系；同目标重复操作幂等 | 仅限同专业、同入学年份且目标组织启用，学籍状态不变 |
| 普通退班 | 按本地当日关闭当前关系；无当前关系时幂等 | 保留账号、学籍状态与历史提交 |
| 重新入班 | 显式选择匹配行政班建立关系 | 只允许在读学生，验证专业、年份和启用状态 |
| 休学、毕业、退学 | 结束当前关系 | 账号仍保留，历史成员和提交不删除 |
| 恢复在读 | 不自动重建关系 | 需要显式重新入班 |
| 转专业、变更入学年份 | 先关闭当前关系；可显式指定新班 | 新班必须匹配变更后的专业与年份；失败整笔回滚，不重写学号或 username |

办理日期由服务端确定，客户端不能回填日期；原入班日期晚于办理当日时拒绝相应操作。普通转班与退班不能直接更改学籍状态，应使用独立学籍接口。

开放学期按当前关系即时调整学生教学班访问；既有作业和提交不迁移到新班。学生本人的历史提交仍保留，教师通过原教学班查看相应教学记录。

## 五、学期生命周期

`AcademicTerm` 包含 `code`、`name`、起止日期、`status`、`is_current`、`closed_at`、`archived_at`。起止日期成对设置且结束不早于开始；历史迁移可保留未确定日期。至多一个学期为当前，当前学期必须开放。切换当前学期不自动结束其他开放学期。

```text
创建 open ── 关闭 ──> closed ── 归档 ──> archived
             冻结名单           冻结逐作业成绩
```

| 阶段 | 前置条件 | 结果 |
|---|---|---|
| 创建/设置当前 | 学期登记有效；设置当前时须为开放状态 | 后续省略 term 的组班使用当前学期编码 |
| 关闭 | 本学期没有未截止作业 | 每个教学班创建唯一冻结记录，保存结课名单；当前标志清除 |
| 评阅收尾 | 学期已关闭，尚未归档 | 教师可写批语、维护和公开截止后的参考答案；禁止发新作业、改组班或新增提交 |
| 归档 | 已关闭，且没有排队或判题中提交 | 保存每个作业成绩表及归档时间，此后教学班写入只读 |

关闭名单取当时学生，并补入有该教学班历史提交的离班学生；其姓名、学号和班级展示数据随名单保存。后续毕业、退班、账号资料调整不改冻结名单。关闭期间允许判题收尾，归档再固定逐题最高有效成绩、提交状态和统计。

教师班级人数、名单、看板和成绩读取使用统一 `classRoster` 与冻结成绩服务。归档成绩导出复用冻结成绩表。课程组知识、章节等可复用资源仍按课程组业务维护；共享资料可以调整关闭学期的指定班范围，涉及归档教学班的范围不能改写或删除，正文与展示元数据仍可维护。

当前接口提供创建、更新开放学期、设置当前、关闭和归档；未提供关闭后重开或反归档操作。真实学期编码与日期由教务登记，系统不从日历推断。

## 六、权限与接口位置

| 范围 | 入口与校验 |
|---|---|
| 教务组班 | 既有 `/api/teaching-classes/`；读需 `course:manage`，组成分配需 `course:assign_class`，任课分配需 `class:assign_teacher` |
| 教务学期 | `/api/office/terms/`；使用 `course:manage` |
| 教务成员和学籍 | `/api/students/` 的档案、memberships、transfer、leave、academic；使用 `class:manage` |
| 教师教学班 | `getTeacherTeachingClass` 核对任课关系；越界 404 |
| 学生既有教学班 | `getStudentTeachingClass` 核对当前在班关系；越界 404 |

新接口参数与错误约定见 [非学生端后端接口.md](非学生端后端接口.md)，权限细节见 [用户权限设计.md](用户权限设计.md)。本轮未增加前端页面或学生自助学籍功能。

## 七、迁移和仍待确认的规则

已有身份、行政班、成员关系和教学班模型已落地。本轮 `academics.0011` 增加课程/行政班启用字段及学期、冻结记录和审计表；`0012` 登记既有字符串学期，并延续原默认学期 `2026-2027-1` 的当前配置。迁移不推断真实开结课日期，也不将已有学期自动关闭或归档。

这些新迁移尚未应用到业务库，必须另行授权、备份和验证。正式学号/工号格式仍待确认；旧 8 位自动分班是占位规则，格式未定时使用指定班级导入。重修、个别学生选课和行政班拆分授课不另建例外映射；如需支持，应单独设计，不能绕过当前原子行政班规则。
