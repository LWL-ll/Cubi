# CodeMind 教辅平台 · 用户与组织模块数据库表重构设计

> 文档性质：用户权限系统数据库表重构的设计定稿（V2 目标态）
> 更新时间：2026-10-18
> 状态：设计定稿 ✅；代码与数据迁移待分阶段实施
> 配套文档：《用户权限设计.md》（权限码与校验机制）、《教学班级设计.md》（教学班）、《架构设计.md》（整体架构）

---

## 一、背景与目标

原设计（V1）用"学号直接当账号 + 四角色一张 User 表 + 学院→班级两层结构"，在吸收外部方案（方案 A：平台账号与学校身份分离）评审后，决定按以下原则重构：

1. **账号与身份分离**：User 只管登录，学号/工号是绑定的学校身份（SchoolIdentity），为将来接入 NSU 教务数据留口子
2. **组织补专业层**：学院 → 专业 → 行政班三层，行政班挂专业下
3. **转班历史留痕**：学生-行政班关系用 memberships 表（joined_at/left_at），转班不覆盖历史
4. **权限体系不动**：四分组 + 22 权限码 + checks.py 一致性检查 + 测试矩阵骨架全部保留

## 二、决策记录（2026-10-18 定稿）

| 决策点 | 结论 | 理由 |
|---|---|---|
| 账号策略 | **封闭式 + 身份表结构** | 账号由教务批量导入创建（学号即 username），导入即 verified；不开放注册，但身份表结构保留，将来开放注册只需加注册/绑定/核验流程 |
| 专业层 | **加** | 教务组织的真实存在；行政班挂专业比挂学院精确 |
| 转班历史 | **加 memberships 表** | 与教学班级设计的"转班自动迁移"衔接；SQLite 无部分唯一索引，一人一班由服务层保证，换 MySQL 后补数据库级约束 |
| 类名与术语 | **College→Department、Clazz→AdminClass** | 与学校教务术语对齐，API 路径同步改 `/api/departments/` |

## 三、目标表结构（V2）

### 3.1 users 应用（账号与身份）—— 4 张业务表

**`users_user`（平台用户主表，几乎不动）**

现有自定义 User（AbstractUser）保留：`username`（学号/工号直登）、`password`、`name`（显示名）、Django 自带字段。分组权限体系照旧。

**`users_schoolidentity`（学校身份表 🆕）**

| 字段 | 类型 | 说明 |
|---|---|---|
| user | FK(User, CASCADE) | 平台账号 |
| school_code | Char(32) | 学校代码，默认 'NSU' |
| school_number | Char(32) | 学号 / 工号 |
| identity_type | Char(16) | student / teacher |
| verification_status | Char(16) | pending / verified / rejected（封闭式下导入即 verified） |
| verified_at | DateTime(null) | 核验时间 |
| created_at | DateTime | 创建时间 |

约束：`UNIQUE(school_code, identity_type, school_number)`（同一学工号只能绑一个账号）+ `UNIQUE(user, school_code, identity_type)`（一人一校一类型一条）。

**`users_studentprofile`（学生资料表 🆕）**

| 字段 | 类型 | 说明 |
|---|---|---|
| identity | OneToOne(SchoolIdentity, CASCADE) | 唯一外键 |
| major | FK(Major, PROTECT) | 所属专业 |
| enrollment_year | SmallInt | 入学年份 |
| academic_status | Char(20) | 在读 / 休学 / 毕业 / 退学 |
| created_at / updated_at | DateTime | 时间戳 |

服务层校验：identity 必须为 `identity_type='student'`。

**`users_teacherprofile`（教师资料表 🆕）**

| 字段 | 类型 | 说明 |
|---|---|---|
| identity | OneToOne(SchoolIdentity, CASCADE) | 唯一外键 |
| department | FK(Department, PROTECT, null) | 所属学院（**档案属性**，不影响课程权限） |
| title | Char(50, blank) | 职称 |
| created_at / updated_at | DateTime | 时间戳 |

课程权限由任课关系（教学班 teachers）决定，与所属学院无关。

### 3.2 academics 应用（组织与课程）—— 6 张业务表

**`academics_department`（学院表，原 College 升级）**

```
code = Char(32, unique)     # 业务编码（新增）
name = Char(100)            # 学院名
is_active = Bool            # 是否启用（新增）
```

**`academics_major`（专业表 🆕）**

```
department = FK(Department, PROTECT)   # 所属学院
code = Char(32)                        # 专业编码
name = Char(100)
is_active = Bool
# unique_together = (department, code)
```

**`academics_adminclass`（行政班级表，原 Clazz 重构）**

```
name = Char(50)                # 班级名（如"计科2301"）
major = FK(Major, PROTECT)     # 所属专业（原 college 改挂 major）
enrollment_year = SmallInt     # 年级/入学年份（新增）
code = Char(32, blank)         # 班级编码（可选）
# unique_together = (major, enrollment_year, name)
```

移除 `students` / `teachers` 两个 M2M——学生关系由 memberships 表承载、教师任课挂教学班。

**`academics_classmembership`（学生-行政班关系表 🆕）**

```
student_profile = FK(StudentProfile, CASCADE)   # 学生
admin_class = FK(AdminClass, CASCADE)           # 行政班
joined_at = DateField()                          # 入班日期
left_at = DateField(null)                        # 离班日期；NULL = 当前在班
```

服务层约束（SQLite 无部分唯一索引，换 MySQL 后补 `UNIQUE(student_profile) WHERE left_at IS NULL`）：
- 同一学生同时只有一个 `left_at IS NULL` 的成员关系
- `left_at >= joined_at`；同一学生的历史记录时间段不重叠

**`academics_course` / `academics_coursecollege`（课程 / 课程×学院，基本不动）**

College 引用改指 Department；`clazzes` M2M 改指 AdminClass（语义：本课程×学院可组教学班的行政班候选池）；组长/教师池机制照旧。

**`academics_teachingclass`（教学班，上轮已定稿，同步术语）**

```
name / term / courseCollege(FK, PROTECT)
adminClasses = M2M(AdminClass)   # 组成行政班（原 clazzes）
teachers = M2M(User)             # 授课教师
```

### 3.3 ER 关系总图（V2 目标态）

```
users_user（平台账号）                       academics_course（课程）
   │ ① identities                            │ course
   ▼                                         ▼
users_schoolidentity（学工号绑定）      academics_coursecollege（课程×学院）
   ├─ ② student_profile ─┐                   │ ③ courseCollege（PROTECT）
   └─ ② teacher_profile  │                   ▼
             │           │           academics_teachingclass（教学班）
             ▼           ▼                   ├─ adminClasses（组成行政班）
users_studentprofile   users_teacherprofile  └─ teachers（授课教师）
   │ ④ memberships        │ department ─────────┐
   ▼                      ▼                    │
academics_classmembership   academics_department（学院）
   │ ④ admin_class             │ department
   ▼                           ▼
academics_adminclass（行政班）◄─ academics_major（专业）

实线 = ForeignKey / OneToOne；虚线 = ManyToMany
```

## 四、新旧表映射

| 旧（V1） | 新（V2） | 数据迁移方式 |
|---|---|---|
| users_user | users_user | 不动（id 不变） |
| — | users_schoolidentity | 🆕 为每个学生/教师账号生成一条（学号/工号=username，verified） |
| — | users_studentprofile / users_teacherprofile | 🆕 按分组生成 |
| academics_college | academics_department | RenameModel（数据保留）+ 自动生成 code（'D' + 自增）+ is_active=True |
| — | academics_major | 🆕 每学院自动建一个「未分类」专业（code='XX00'），后续教务手动细化 |
| academics_clazz | academics_adminclass | RenameModel + 加 major FK（先填「未分类」专业）+ enrollment_year 从班名/学号解析 |
| academics_clazz_students（M2M） | academics_classmembership | 数据迁移：每条生成 joined_at=当天、left_at=NULL |
| academics_clazz_teachers（M2M） | teachingclass.teachers | 数据迁移：为每个 (行政班, 课程×学院) 组合建 1:1 教学班（term 占位 '2026-2027-1'），教师并入 |

## 五、权限体系影响

| 层 | 影响 |
|---|---|
| 认证层 | 不动：学号直登、axes 防爆破、登出仅 POST |
| 功能级 | 不动：四分组 + 22 权限码 + checks.py 一致性检查 |
| 对象级 | **锚点改变**：`getStudentClazz` 改为 `getStudentTeachingClass`（学生 → membership → 行政班 → 教学班三跳）；`getTeacherClazz` 改为 `getTeacherTeachingClass`（教学班 teachers 一跳）；教务上下文 course→department→教学班 |

users/permissions.py 的 8 个工具与 teaching/tests.py 测试矩阵骨架全部保留，测试数据构造改为新表结构。

## 六、学号解析规则调整（academics/student_no.py）

占位规则由「4 年级 + 2 学院 + 2 班级序号」调整为「**4 年级 + 2 专业 + 2 班级序号**」：

```
8 位数字 = YYYY + MM + NN
          │年级 │专业代码 │班级序号
```

学院不再由学号直接解析，改由"专业 → 学院"推导。真实学号格式定稿后仍只改这一个文件（原则不变）。

## 七、数据迁移方案（现有 db.sqlite3）

1. `makemigrations`：模型重构（RenameModel + 新表 + 新字段），数据保留
2. 数据迁移脚本（按第四节映射表）：身份表生成、资料表生成、未分类专业、memberships 填充、教学班生成
3. 校验：`manage.py check`（权限一致性）+ 三应用测试矩阵
4. 教务手动调整：专业细化、班级挂对专业、教学班组班

## 八、分阶段落地计划

| 阶段 | 内容 | 影响面 |
|---|---|---|
| ① 模型重构 | users/academics models.py 新表 + RenameModel 迁移 | 全部 API 因表名/字段变化暂不可用 |
| ② 数据迁移 | 第七节迁移脚本 + 校验 | 数据无损 |
| ③ 教务端改造 | academics api/views/serializers/urls（departments、majors、adminclasses、memberships CRUD + 导入改造） | 教务功能恢复并增强 |
| ④ 教学端改造 | teaching helpers/api/views（对象级校验三跳 + 教学班数据源） | 教师/学生功能恢复 |
| ⑤ 测试重构 | 三应用测试矩阵按新表重写，全绿收尾 | 回归保障 |
| ⑥ 文档收尾 | 架构设计/API 设计/项目结构讲解同步 | 文档一致 |
