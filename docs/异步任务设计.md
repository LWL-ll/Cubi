# CodeMind 教辅平台 · 异步任务设计

> 更新时间：2026-10-27。本文描述当前代码；业务数据库迁移和新增 worker 部署仍需分别验收。
> 相关文档：[非学生端后端接口](非学生端后端接口.md)、[API 设计文档](API设计文档.md)、[OJ 对接设计](OJ对接设计.md)。

## 1. 当前实现边界

| 业务 | 记录模型 | 执行方式与入口 |
|---|---|---|
| 教务 xlsx 导入 | `tasks.OfficeImportJob` | `POST /api/import-jobs/` 受理，由默认 `codemind` Q2 集群分段执行 |
| 公共／教师个人题库 ZIP 导入 | `tasks.AsyncTask(type='import')` | 在请求内同步导入，记录批次历史；教师个人历史入口为 `/api/teacher/problems/imports/` |
| OJ 判题 | `teaching.JudgeTask` | `long` 集群执行，使用独立判题租约与提交快照 |
| Agent 讲题接入点 | `teaching.AgentTutorReport` | `agent` 集群预留接入，`AGENT_ENABLED` 默认关闭，Agent 本体尚未接入 |

`AsyncTask` 中的 AI、提醒类型仍是占位，不代表已实现通用异步 AI 批改或邮件／短信提醒。当前作业提醒是站内记录。通用 `/api/tasks/` 与 `/api/tasks/<id>/` 查询接口没有实现。

已有 `/api/import/` 及指定班级／课程教师的旧导入动作仍是同步入口；本轮新增后台批次接口，旧接口响应不变。较大批次应使用 `/api/import-jobs/`。

## 2. 运行进程与队列

使用 `django-q2`，broker 为 Django ORM，不需要 Redis。Web 进程、默认导入 worker 和判题 worker 分别运行。只运行 `long` worker 时，教务导入与其回收排程不会被消费。

| 集群 | 当前配置 | 职责 |
|---|---|---|
| `codemind` | `workers=2`、`timeout=600` 秒、`retry=700` 秒、`max_attempts=2` | 教务导入及导入超时／文件回收 |
| `long` | `timeout=900` 秒、`retry=1000` 秒 | OJ 判题及判题租约回收 |
| `agent` | `timeout=1800` 秒、`retry=1900` 秒 | Agent 讲题预留任务，当前默认不开启 |

默认集群还设置 `queue_limit=50`、`orm='default'`、`poll=0.5`、`catch_up=False`、`ack_failures=True`。`retry` 大于 `timeout`；Q2 的重投机制与业务批次的手动重试是两件事。

在项目目录、相同 Python 环境和数据库配置下，默认 worker 命令为：

```console
python manage.py qcluster
```

该进程应不带 `Q_CLUSTER_NAME=long`。Linux 判题 worker 在另一个常驻进程运行：

```console
Q_CLUSTER_NAME=long python manage.py qcluster
```

宝塔／进程管理器应分别维护 Web、`codemind`、`long` 进程，配置异常重启；默认 worker 的调度器必须启用。各进程需要访问同一私有文件目录，不能把它配置为公开媒体目录。以上是部署要求，不表示本轮已操作生产进程。

## 3. 教务导入 API

接口实现为 `tasks/import_api.py`，路由位于 `tasks/import_urls.py`，业务逻辑位于 `tasks/import_service.py` 与 `tasks/tasks_import.py`。完整参数与其他教务接口见[非学生端后端接口](非学生端后端接口.md)。

所有批次接口要求有效登录和 `class:manage`。普通用户只可访问自己提交的批次；超级管理员可访问全部；访问他人批次返回 404。响应使用 `Cache-Control: private, no-store`。

| 方法与路径 | 请求及结果 |
|---|---|
| `POST /api/import-jobs/` | multipart：`type`、`file`，按类型允许 `adminClassId` 或 `courseCollegeId`；受理返回 202 和批次对象 |
| `GET /api/import-jobs/` | 可选 `page`、`type`、`status`；每页 20 条，返回 `{count, page, results}` |
| `GET /api/import-jobs/<id>/` | 返回当前批次对象，可供轮询进度 |
| `POST /api/import-jobs/<id>/retry/` | multipart，仅 `file`；重新上传后返回 202，沿用批次 ID、递增 `attempt` |
| `GET /api/import-jobs/<id>/errors/` | 可选 `page`；每页 100 条，返回 `{count, page, results: [{line, reason}]}` |
| `GET /api/import-jobs/<id>/errors/download/` | 下载带 UTF-8 BOM 的错误 CSV，包含物理行号与错误原因，危险公式前缀已转义 |

`page` 范围为 1～999999。列表按创建时间及 ID 倒序。批次对象由 `serializeImport()` 输出以下字段：

```text
id, type, status, originalName, createdBy, adminClassId, courseCollegeId,
total, completed, progress, successCount, errorCount, error, attempt,
retryable, createdAt, startedAt, finishedAt
```

`total` 是非空有效数据行数；`completed` 是已处理的有效行数；`progress = completed * 100 // total`。`errorCount` 表示逐行失败数，`error` 表示入队、超时、撤权等批次级失败，两者需分别展示。批次级失败可能发生在部分行已成功之后，进度无需达到 100%。错误列表从独立接口读取，不嵌入详情。

### 导入类型与权限

| `type` | 额外参数 | 权限及行为 |
|---|---|---|
| `course` | 无 | 额外要求 `course:manage`，导入课程编号和名称 |
| `teacher` | 无 | 导入教师账号、教师身份与档案 |
| `student` | 无 | 保留现有学号解析和自动分班规则；正式学号规则仍待确认 |
| `class_student` | `adminClassId` 必填 | 导入指定行政班，不依赖旧自动学号分班规则 |
| `course_teacher` | `courseCollegeId` 必填 | 额外要求 `class:assign_teacher`；导入教师并加入课程教师池，按现有业务服务分配可写学期的任课关系 |

其他类型不接受目标参数。目标行政班／专业／学院或目标课程停用时拒绝相应导入。worker 开始执行及每个有效行之前，都重新加载提交人并检查账号启用状态、权限和目标；重试仍以原提交人的权限执行，管理员重试不会转移批次归属。

### 文件预检

- 仅 `.xlsx`，最大 10MiB；ZIP 解压内容总量最大 64MiB，不接受加密文件。
- 只读取活动工作表，跳过第一物理行；最多 10000 个数据物理行，空白行也占此上限。
- A 列为编号，B 列为姓名／课程名称，账号导入的 C 列为初始密码；A～C 之外不能填写非空内容。
- 空白行不计入 `total`，失败行号保留 Excel 物理位置；至少有一个非空数据行才能受理。
- 每个提交人同时最多 3 个 `pending`／`running` 批次。

首请求仍同步完成文件安全预检及总量统计；账号创建和逐行导入在后台执行。新建账号标记首次登录必须改密。

## 4. 状态、分段和幂等

`OfficeImportJob` 的状态为 `pending`、`running`、`succeeded`、`partial`、`failed`。

```text
pending → running → succeeded / partial / failed
             ↓
          pending → running   （同一批次后续分段）

partial / failed → pending    （手动重新上传，attempt 加 1）
```

全部行成功为 `succeeded`；成功和错误行并存为 `partial`；全部行失败或批次执行异常为 `failed`。活动批次与全部成功批次不能手动重试。`retryable` 只表示状态具备重试资格，仍须满足权限、文件清理和上传要求。

受理时先保存私有源文件和批次，在数据库事务提交后投递 `tasks.tasks_import.runOfficeImport(jobId, attempt)`。队列只接收批次 ID 与轮次，不接收表格、文件路径、原始密码或请求对象。入队异常会将仍待处理的对应轮次置为失败并清理源文件。

worker 通过 `id + attempt + pending + 未过期` 的条件更新领取任务。每个物理行处理前锁定批次记录；业务行导入、成功／错误计数和 `row_cursor` 在同一事务中提交。行失败不回滚前面已完成的行；异常也不会留下账号已创建而游标未提交的半行状态。

每次最多处理 100 个有效行，或在行结束后发现该段已运行约 60 秒，即保存为 `pending` 并在提交后续投；最后一段写终态。后续段跳过已提交的物理游标，保留首次 `startedAt`，不增加 `attempt`。60 秒是行间分段判断，不会在单行事务中强行截断。

同轮次重复消息只有一个能领取当前段；旧轮次消息无法执行新轮次。手动重试必须重新上传，可只上传修正后的失败行；新轮次重新计算总量和计数，沿用原类型与目标。已有用户名／课程编号按原导入逻辑报重复并跳过，不覆盖已有姓名或密码。

## 5. 超时与私有源文件生命周期

源文件位于 `PRIVATE_MATERIAL_ROOT/office_imports/<随机 UUID>.xlsx`。接口不提供源文件下载，也不返回存储标识、目录、原始行或初始密码。文件保留期间可能含初始密码，必须限制目录访问，不能由 Nginx 或 Django 媒体路由公开。

| 情况 | 处理 |
|---|---|
| 正常终态／入队失败 | 删除源文件并清空记录中的存储标识 |
| 删除失败 | 保留存储标识，回收任务继续重试；旧文件未清理前禁止用重试覆盖标识 |
| 排队超过 24 小时 | 批次置为 `failed`，删除源文件，用户重新上传重试 |
| 单段运行超过执行截止时间 | 批次置为 `failed`，保留已提交行统计并清理源文件；默认截止为 `max(120, Q_CLUSTER.timeout) + 60`，当前为 660 秒 |
| 建批次前进程退出等产生孤儿文件 | 回收超过 24 小时、名称符合本服务 UUID 格式且没有任何批次引用的文件 |

`tasks.tasks_import.recoverOfficeImports()` 执行过期批次处理、失败删除重试和孤儿清理；列表／详情读取也会回收其可见范围中的超时批次。进程被杀后不承诺自动继续剩余行，超时批次经回收成为可重新上传的失败状态。

迁移 `tasks/0005_office_import_recovery_schedule.py` 幂等注册排程 `office-import-recovery`：每分钟执行一次，集群为 `codemind`。注册数据库排程不能替代运行默认 worker 与调度器；进程停止期间不会执行清理。已有 `judge-lease-recycle` 排程继续属于 `long` 集群。

批次完成只向审计写入类型、状态、轮次和计数等安全元数据。预期逐行错误使用业务文案，未知异常只返回固定错误；不把原始密码或内部路径放入结果、队列与导入任务日志。

## 6. 迁移与验证

新增迁移为 `tasks 0004`（`OfficeImportJob` 表）及 `tasks 0005`（回收排程）。开发测试库会执行这些迁移；业务数据库尚需用户单独授权、备份和迁移验收后才能更新，文档更新不代表已迁移生产数据。

```console
python manage.py makemigrations tasks --dry-run --check
```

这些测试直接执行任务函数并控制提交回调，不表示已验收生产 `codemind` worker 的真实消费。部署时还需验证受理后任务被默认集群领取、进度推进、终态源文件删除及每分钟回收排程执行；OJ 的真实队列验收按 OJ 专门文档进行。
