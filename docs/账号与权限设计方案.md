# CodeMind 教辅平台 · 账号与权限设计方案

> 状态：设计中（待补充学号/工号格式规则）
> 更新时间：2026-10-12
## 一、总体原则

- **安全性第一**：生产级交付标准，密码永不落库明文、防暴力破解、服务端强制鉴权
- **无注册界面**：所有账号由系统统一导入，学生/教师/教务均无自助注册入口

## 二、账号体系

### 2.1 账号规则

| 用户类型 | 登录账号 | 说明 |
|---|---|---|
| 学生 | 学号 | 有固定格式，按格式匹配 |
| 教师 | 工号 | 有固定格式，按格式匹配 |
| 教务 | 工号 | 有固定格式，按格式匹配 |

- 登录时后端按**固定格式规则**识别输入的是学号还是工号，直接查库，登录框无需选身份
- `username` 数据库唯一约束兜底防撞号
- **待确认**：学号格式 = ?（如 8 位纯数字）；教师工号格式 = ?；教务工号格式 = ?

### 2.2 账号导入（系统统一操作，无注册页）

1. **教务账号：由系统管理员在 `/admin/` 后台添加**（创建用户并勾选「教务」分组）——教务不参与批量导入，谁有教务权限完全由管理员掌控
2. **教师/学生批量导入**：教务工作台 xlsx 上传（工号/学号、姓名、初始密码），教师入「教师」分组、学生按学号格式自动分班入「学生」分组
3. **CSV 批量导入命令**（规划中）：`python manage.py importusers 名单.csv`
   ```csv
   角色,编号,姓名,初始密码
   student,20231001,张三,Abc12345
   teacher,T1001,李老师,Abc12345
   ```
   - 密码自动哈希入库；重复编号自动跳过并报告；密码强度校验
4. **教师专有权限固定在「教师」分组**（通知/学情/作业/资料等），分组权限随导入自动生效，无需逐人配置

## 三、用户分组与权限

### 3.1 超级用户（superuser）

- Django 原生 superuser，**不参与四个分组**，拥有全部权限
- 作为后台管理员使用；后台管理功能范围**暂定，后轮细化**

### 3.2 四个用户分组（Django 原生 Group）

| 分组 | 说明 | 注册/创建方式 |
|---|---|---|
| 教务 | 管理全校班级、课程 | 系统导入 |
| 课程组 | 资料管理、题库管理、课程章节 | **不开放导入**，由教务在系统内指定（把教师加入课程组分组） |
| 教师 | 班级通知、作业、资料 | 系统导入 |
| 学生 | 作业、个人资料 | 系统导入 |

### 3.3 权限点（按 xmind《用户权限》逐条翻译）

**教务：**
- `class:manage` 全校班级增删改查
- `class:assign_teacher` 分配教师
- `course:manage` 全校课程增删改查
- `course:assign_class` 分配班级
- `user:assign_role` 指定课程组组长（预留）

**课程组（2026-10-13 按《课题组.xmind》重新设计，✅ 已落地）：**
- `knowledge:manage` AI Agent知识库增删改查
- `material:class_visible` 课程下班级资料增删改查
- `question_bank:manage` 作业题库增删改查
- `chapter:manage` 课程章节设计

> 说明：旧 `material:manage`（课程组资料管理）已删除（迁移 0007），资料被拆成两类分别增删改查（知识库 / 课程下班级资料）。

**教师（2026-10-13 按《教师.xmind》重新设计，✅ 已落地）：**
- `notice:manage` 班级通知增删改查
- `analysis:view` 班级学情分析图表查看（仅查看）
- `material:class_manage` 班级内部资料增删改查
- `homework:publish` 作业发布
- `homework:bank` 作业题库管理
- `homework:remind` 作业提醒
- `homework:comment` 作业评语增删改查
- `homework:answer` 作业答案改查
- `homework:ai` Agent 分析学生改查

> ⚠️ **教师的所有权限仅限教学班级**：除分组权限外，业务接口还必须做对象级校验（校验班级教师表是否包含当前用户）。分组权限码只回答"教师能不能用这个功能"，对象级校验回答"能不能对这个班用"。
>
> 📌 附带业务规则：**作业无法删除已截止作业**（发布/截止后不可删）。
>
> 说明：旧 `homework:collect` 已拆分并删除（迁移 0005）；教师不再拥有课程组资料权限 `material:manage`，课程组资料仍由课程组管理。

**学生（预留）：**
- `homework:view` 作业（查看/提交）
- `profile:edit` 修改个人资料

**所有角色通用：**
- `profile:edit` 修改个人资料

### 3.4 技术实现

- 权限码注册为 Django 原生 Permission（User.Meta.permissions）
- 四个 Group 由数据迁移自动创建并分配权限
- 视图层统一 `@require_perm('class:manage')` 装饰器强制校验（后端强制，前端隐藏按钮不作防线）

## 四、登录与安全

### 4.1 登录流程

1. 输入账号（学号/工号）+ 密码
2. 后端按格式规则识别账号类型 → 查库认证
3. django-axes 防暴力破解：连续失败 5 次锁定 1 小时，日志可审计
4. 登录成功 → 跳转首页（按分组显示对应功能入口）

### 4.2 安全配置清单

| 项 | 状态 |
|---|---|
| 密码 PBKDF2 哈希存储 | ✅ Django 内置 |
| 密码强度校验器 | ✅ settings 默认启用 |
| django-axes 登录限流 | ✅ 本轮安装配置 |
| CSRF 防护 | ✅ Django 中间件默认 |
| Session 安全（HttpOnly 等） | ✅ 本轮加固 |
| 服务端权限强制校验 | ✅ `@require_perm` 装饰器 |
| 输入校验（格式/唯一性/强度） | ✅ 后端全部再校验 |
| **首次登录强制修改初始密码** | ⏸️ **暂缓，交付前必补**（含防绕过中间件） |
| 交付时 DEBUG=False、SECRET_KEY 环境变量 | 📌 交付前执行 |

### 前后端分离约定（2026-10-12 确定）

- 主线：**后端 API + 用户权限划分**；前端独立开发（暂未定框架），现有模板页面仅作开发预览保留
- xlsx 导入列约定：A 列编号（学号/工号/课程编号）、B 列姓名/课程名称、C 列初始密码，第一行为表头
- 学号格式隐含年级/班级/学院信息、课程编号规则：**待用户研究定稿**（导入解析需按格式自动分配班级/学院）
- API 权限码映射：课程列表/详情=course:manage、分配班级=course:assign_class、班级=class:manage、分配教师=class:assign_teacher、导入课程=course:manage、导入教师/学生=class:manage、设课程组组长=user:assign_role
- 学号占位规则（`academics/student_no.py`，定稿前用于演示）：8 位数字，前 4 位年级、第 5-6 位学院代码（10=计算机/11=外国语/12=数学）、第 7-8 位班级序号；班级名=专业名+年级后两位+班序（如 20231001 → 计算机学院 计科2301）

### 技术笔记（踩坑记录）

- **django-axes 8.x 认证后端必须两个配合**：`AxesStandaloneBackend`（只拦截锁定，不认证）+ `ModelBackend`（真正认证），只配前者会导致所有登录失败
- **数据迁移里查不到 Meta.permissions 的权限记录**（post_migrate 信号才入库），需在迁移内用 `get_or_create` 自行创建（见 users/migrations/0002）
- 项目 conda 环境：`codemind`（Django 6.1.2），运行命令统一用
  `conda run -n codemind python manage.py ...`
