## 一、数据模型层

### 1.1 教学业务模型（5 张表，全部未建）

> 现状：`teaching/models.py` 仅含规划注释。全部外键到 `Clazz`（班级为容器），沿用对象级校验思路。

**① Notice 班级通知**

```python
# 字段草案
clazz       = FK(Clazz, CASCADE, related_name='notices')   # 归属班级
author      = FK(User, SET_NULL, null=True)                # 发布教师
title       = CharField(100)
content     = TextField
is_pinned   = BooleanField(default=False)                  # 是否置顶
created_at / updated_at
```

决策点：是否需要已读回执（学生端"未读数"）？置顶是否需要？

**② ClassMaterial 班级内部资料**

```python
clazz       = FK(Clazz, CASCADE, related_name='materials')
uploader    = FK(User, SET_NULL, null=True)
title       = CharField(100)
file        = FileField(upload_to='materials/%Y%m/')       # 依赖 1.5 MEDIA 配置
file_size   = PositiveIntegerField                        # 落库冗余，展示免查文件系统
created_at
```

决策点：删除资料时是否物理删文件；文件名是否保留原名。

**③ Homework 作业**

```python
clazz       = FK(Clazz, CASCADE, related_name='homeworks')
publisher   = FK(User, SET_NULL, null=True)
title       = CharField(100)
content     = TextField
deadline    = DateTimeField                               # 截止时间，核心字段
created_at / updated_at
```

业务规则（模型层+服务层双保险）：
- `deadline` 已过 → 禁止 PATCH/DELETE（403 或 400），规则封装成模型方法 `is_closed()` 供服务层调用
- 若引入学期（见 1.2），需追加 `semester` FK

**④ HomeworkSubmission 作业提交**

```python
homework    = FK(Homework, CASCADE, related_name='submissions')
student     = FK(User, CASCADE)
content     = TextField(blank=True)                       # 文字作答
attachment  = ImageField/FileField(blank=True, null=True) # 拍照提交（若保留）
submitted_at = DateTimeField(auto_now_add=True)
updated_at  = DateTimeField(auto_now=True)
# 批改侧
comment     = TextField(blank=True)                       # 教师评语
answer_ref  = TextField(blank=True)                       # 教师给出的答案/讲解
commented_by = FK(User, SET_NULL, null=True)
```

决策点：
- `unique_together(homework, student)` 一人一作业仅一条提交记录，重复提交走更新（推荐）还是允许多条（历史留痕）？
- 截止后是否允许补交（`deadline` 与 `submitted_at` 的比较规则、是否需要 `is_late` 标记）
- 附件类型白名单（jpg/png/pdf?）与大小上限

**⑤ QuestionBank 教师个人题库**

```python
owner       = FK(User, CASCADE, related_name='questions')  # 题目归教师本人
clazzes     = M2M(Clazz)                                    # 仅限自己执教班级使用
qtype       = CharField(choices=['single','multiple','blank','essay'])
stem        = TextField                                    # 题干
options     = JSONField(blank=True)                        # 选择题选项
answer      = TextField(blank=True)                        # 标准答案
analysis    = TextField(blank=True)                        # 解析
created_at / updated_at
```

决策点：课程组题库（`question_bank:manage`）与个人题库是两套模型还是共享一套加 `owner` 区分？选择题自动判分是否一期做（影响 Submission 增加 `score` 字段）？

### 1.2 学期维度（全库重构风险，最高优先决策）

> 现状：`CourseCollege` 为 `unique_together(course, college)` —— 同一课程在同一学院只能开设一次。下学期重开同一课程直接冲突。

**若系统跨学期使用**：
- 新增 `Semester` 模型（name/year/start_date/end_date/is_active）
- `CourseCollege` 唯一约束改为 `(course, college, semester)`
- 所有教学业务表（Notice/Homework/Submission）挂 `semester` FK 或通过 clazz 间接定位学期
- 教务工作台需加"当前学期"上下文切换

**若一期仅服务一个学期**：维持现状，但需在设计中显式声明，避免二期重构。

### 1.3 学生状态与转班

> 现状：一个学生只属一个班级（导入时强制），无状态字段。

- 是否需 `is_active` 之外的状态（休学/毕业）？建议加 `status` 字段或利用 Django 自带 `is_active`
- 转班 = 移动 `clazz.students` M2M 关系；**历史作业提交记录归属旧班级如何处理**（保留原记录不迁移 / 迁移到新班）——必须在动工前定
- API 层需加服务端约束：任何写学生-班级关系的入口都要校验"一个学生仅一个班"

### 1.4 作业业务规则落点

| 规则 | 落点 |
|---|---|
| 截止后不可删改作业 | 模型方法 `is_closed()` + 服务层 + 序列化器校验三重 |
| 学生仅见自己班级作业 | `getStudentClazz` 对象级校验 |
| 教师仅批改执教班级 | `getTeacherClazz` + submission→homework→clazz 链路校验 |
| 无法删除已截止作业 | DELETE 接口服务层拦截 |

### 1.5 文件上传地基（当前完全缺失）

> 现状：settings.py 无 `MEDIA_ROOT` / `MEDIA_URL`。班级资料、作业图片提交都依赖它。

- 配置：`MEDIA_ROOT = BASE_DIR / 'media'`、`MEDIA_URL = '/media/'`
- 上传校验：类型白名单（扩展名 + MIME 双重校验）、单文件大小上限（如 20MB）、总容量告警
- 生产环境：媒体文件不入 git（.gitignore）、随备份策略纳入
- **受保护下载**：媒体文件若直接由静态服务器暴露，知道 URL 即可下载，绕过对象级校验 —— 见 2.6

### 1.6 数据库索引规划（建表时同步加，不后补）

| 表 | 高频查询 | 建议索引 |
|---|---|---|
| Notice | 按班级查最新 | `(clazz, created_at)` |
| Homework | 按班级+截止时间查 | `(clazz, deadline)` |
| HomeworkSubmission | 按学生查、按作业查 | `unique(homework, student)` + `(student, homework)` |
| ClassMaterial | 按班级查 | `(clazz, created_at)` |

## 二、API 层

### 2.1 教师业务 API（9 个权限码对应接口全空）

> 现状：`/api/teacher/` 仅 clazzes 列表/详情两接口。以下为端点草案，**每个接口必须套 `getTeacherClazz` 对象级校验**（否则越权）。

```
班级通知（notice:manage）
POST   /api/teacher/clazzes/<id>/notices/           发通知
PATCH  /api/teacher/clazzes/<id>/notices/<nid>/     改通知
DELETE /api/teacher/clazzes/<id>/notices/<nid>/     删通知

班级资料（material:class_manage）
GET    /api/teacher/clazzes/<id>/materials/         资料列表
POST   /api/teacher/clazzes/<id>/materials/         上传（multipart）
DELETE /api/teacher/clazzes/<id>/materials/<mid>/   删除

作业（homework:publish / homework:remind）
POST   /api/teacher/clazzes/<id>/homeworks/         发布
PATCH  /api/teacher/clazzes/<id>/homeworks/<hid>/   修改（截止后 403）
DELETE /api/teacher/clazzes/<id>/homeworks/<hid>/   删除（截止后 403）
GET    /api/teacher/clazzes/<id>/homeworks/<hid>/submissions/   收作业列表
PATCH  /api/teacher/clazzes/<id>/homeworks/<hid>/submissions/<sid>/  评语+答案（homework:comment/answer）
POST   /api/teacher/clazzes/<id>/homeworks/<hid>/remind/          提醒未交学生（homework:remind）

学情分析（analysis:view）
GET    /api/teacher/clazzes/<id>/analysis/          班级画像数据

个人题库（homework:bank）
GET/POST    /api/teacher/question-bank/
PATCH/DELETE /api/teacher/question-bank/<qid>/

AI 批改（homework:ai，若一期保留）
POST   /api/teacher/clazzes/<id>/homeworks/<hid>/ai/   触发 Agent 分析
```

### 2.2 学生端 API（连接口壳都没有）

```
作业（homework:view）
GET  /api/student/homeworks/           我的班级作业列表（含提交状态）
GET  /api/student/homeworks/<hid>/     作业详情
POST /api/student/homeworks/<hid>/submit/   提交/更新提交（multipart 支持图片）

画像（analysis:view_self）
GET  /api/student/analysis/            个人画像数据

资料（profile:edit）
GET/PATCH /api/student/profile/        查看/修改个人资料
```

校验链：`requireStudentGroup` → `getStudentClazz` → 作业必须属于学生所在班级。

### 2.3 课程组 API（4 项权限码全空）

```
knowledge:manage        AI Agent 知识库 CRUD（依赖 4.4 AI 形态决策）
material:class_visible  课程下班级资料的可见性管理（跨班级视角）
question_bank:manage    课程组题库 CRUD（与教师个人题库的模型关系待定）
chapter:manage          课程章节设计 CRUD（章节树：Chapter → Section）
```

### 2.4 新接口开发检查单（每写一个接口过一遍）

1. 功能级：视图声明 `permCode`（PermRequired 自动校验）
2. 入口级：教师接口挂 `IsTeacherGroup`、学生接口挂学生组校验
3. **对象级：`getTeacherClazz` / `getStudentClazz`（越界返回 404，不暴露存在性）**
4. 动作级：写操作按权限码细分（如 publish 与 remind 分开）
5. 响应格式统一 `{"error": ...}`，错误语义遵循 400/403/404 约定

### 2.5 分页 / 过滤 / 排序

> 现状：DRF 未配 `DEFAULT_PAGINATION_CLASS`，列表接口无分页。真实班级的作业列表、提交列表会爆。

- 列表接口统一分页（如 `PageNumberPagination`，page_size=20，返回 total）
- 提交列表按学号/姓名排序、按"已交/未交"过滤；作业列表按 deadline 倒序

### 2.6 受保护的文件下载（防绕过对象级校验）

| 方案 | 实现 | 优缺点 |
|---|---|---|
| Django 视图代理（一期推荐） | 下载走 `GET /api/teacher/clazzes/<id>/materials/<mid>/download/`，先过 `getTeacherClazz` 再用 `FileResponse` 流式返回 | 实现简单；大文件占 Django 进程资源 |
| Nginx X-Accel-Redirect（生产） | 视图校验后返回 `X-Accel-Redirect` 头，由 Nginx 直接发文件 | 性能好；依赖 Nginx 部署与 internal 配置 |

### 2.7 API 版本化

`/api/` 无版本前缀。若前端联调中接口会变，建议加 `/api/v1/`（或至少文档中声明兼容策略），避免上线后前端无法升级。

### 2.8 异步任务设计

> 详细设计已单独成文：《异步任务设计.md》。本节仅保留结论。

**问题**：全同步架构，批量导入的密码哈希是 CPU 密集操作（PBKDF2 约 60~100ms/次，1 万学生仅哈希 ≈ 10~16 分钟），生产 Nginx 60s 超时必然中断；AI 批改（LLM 10~60s）同步必死。

**方案**（详见《异步任务设计.md》）：
- 选型 **django-q2**（Django ORM 做 broker，Windows 兼容，零额外中间件，内置定时任务）
- 统一任务表 `AsyncTask`（新应用 `tasks`）：状态机 pending→running→done/failed + progress + result/error
- 接口改「提交→轮询」：`POST /api/import/` 受理后返回 taskId，`GET /api/tasks/`、`GET /api/tasks/<id>/` 查进度（created_by 过滤，越界 404）
- 任务函数为模块级纯函数：worker 内重新加载 userId 做权限校验（权限延续）、按编号查重保证幂等、错误脱敏进日志、终态清理临时文件
- 定时任务（schedule）：会话清理、临时文件孤儿清理、作业截止提醒（后续轮次）

## 三、认证与账号安全

### 3.1 首次登录强制改密（交付前必补，未动工）

实现链路：
1. `users.User` 增加 `must_change_password = BooleanField(default=...)`（导入创建时置 True）
2. 登录接口响应中返回该标志，前端据此强制跳改密页
3. 新增 `POST /api/auth/change-password/`（校验旧密码 + 新密码强度），成功后置 False
4. 后端兜底：`must_change_password=True` 时，除改密/登出外的业务接口一律拒绝（中间件或权限类实现，不能只靠前端跳转）

### 3.2 找回 / 重置密码（零实现）

| 方案 | 依赖 | 适用 |
|---|---|---|
| 邮箱验证码/链接 | 真实 SMTP 配置（现在还是 console backend） | 学校邮箱体系可用时 |
| 管理员重置 | 仅超管在 /admin/ 操作 | 小规模、一期过渡 |

### 3.3 改密后的会话处理

- 自己改密：`update_session_auth_hash` 保持当前会话（推荐）或强制重登
- 管理员重置他人密码：应使该用户旧会话失效（可对比 password 哈希变化或记录 `password_changed_at` 校验会话签发时间）

### 3.4 JWT vs Session（前后端分离的架构决策）

| 方案 | 需要补 | 适合 |
|---|---|---|
| 维持 Session + Cookie | django-cors-headers、CSRF_TRUSTED_ORIGINS、跨域下 SameSite 策略重审（当前 Lax） | 同域部署（Nginx 反代前端同域） |
| 上 JWT | 引入 SimpleJWT、重写认证类、前端存储与续期策略 | 前后端跨域独立部署 |

## 四、业务逻辑暗坑

### 4.1 作业提醒的实现（homework:remind）

- 站内信方案：需新建 Message 模型（receiver/内容/已读状态），学生端加"消息"入口
- 邮件方案：依赖 SMTP，实时性差
- **同步 or 异步**：批量提醒（一个班几十人）若同步发会阻塞请求，需 Celery/Django-Q 或先同步做一期、观察耗时

### 4.2 批量导入的规模问题

> 现状：xlsx 导入为同步请求。几万学生时可能超时（生产 Nginx 默认 60s）。

- 一期：保持同步 + 前端 loading + 超时上限说明
- 二期：异步任务 + 导入进度查询接口

### 4.3 学生唯一分班约束的服务端兜底

- 现有实现依赖导入逻辑，API 层没有统一校验
- 建议：任何写学生-班级关系的代码路径收敛到一个服务函数（如 `academics/services.py` 的 `assignStudentToClazz`），内部强制唯一性

### 4.4 学情画像的指标定义（纯后端问题）

`analysis:view` / `analysis:view_self` 返回什么，需先定指标再写接口：

| 指标（草案） | 计算来源 |
|---|---|
| 作业完成率 | 已提交数 / 应提交数（HomeworkSubmission） |
| 提交及时性 | 按时提交占比（submitted_at vs deadline） |
| 正确率 | 若有自动判分 score 字段；无则仅统计完成情况 |

### 4.5 AI 功能形态（最大延期风险，建议一期砍或降级）

- `homework:ai`（Agent 分析学生作业）、`knowledge:manage`（知识库）依赖 LLM
- 三个选项：接大模型 API（费用+学生数据出校的隐私问题）/ 本地模型（部署成本）/ 规则版占位（字数、关键词统计，二期升级）
- **建议：一期用规则版占位，接口结构按可替换设计（Service 层隔离），二期换 AI 不动接口**

## 五、工程化与生产化

### 5.1 配置分离（settings.py 欠账）

| 项 | 现状 | 改造 |
|---|---|---|
| SECRET_KEY | 硬编码 + `django-insecure` 前缀，已进 git | 环境变量注入，换新密钥 |
| DEBUG | True | dev/prod 分离（`settings/dev.py` + `settings/prod.py`） |
| ALLOWED_HOSTS | 仅 localhost | 按部署域名配置 |
| 静态文件 | 无 STATIC_ROOT | 补 `STATIC_ROOT`，部署 collectstatic |
| 邮件 | console backend | 按找回密码方案切换真实 SMTP |
| 日志 | LOGGING 未配置 | 文件+控制台双 handler，按模块分级 |

### 5.2 数据库切换（SQLite → MySQL/PostgreSQL）

- 高峰期多人提交作业时 SQLite 有锁库风险
- 切换步骤：新库迁移 → 数据导出导入（dumpdata/loaddata 或手工）→ 连接配置环境变量化
- 注意：MySQL 与 SQLite 的字段长度/唯一约束差异，迁移后跑全量测试

### 5.3 定时任务

若需要"截止自动归档""定时提醒"：Django 无内置，需 Cron（简单）或 Celery beat（重）。

### 5.4 测试覆盖补全

- 现状：仅 users 权限矩阵；academics 有部分测试
- 每个功能轮次必须带：模型约束测试 + API 集成测试 + **越权场景矩阵**（四角色 × 端点，沿用 users/tests.py 的模式）
- 对象级校验专项：非执教班级教师访问 → 404；非本班学生提交作业 → 404

### 5.5 现有代码复查项

- 班级列表等接口的查询策略过一遍 `select_related` / `prefetch_related`（N+1 隐患，可用 dj-orm-opt 技能审查）
- `db.sqlite3`、`__pycache__` 被 git 跟踪，补 .gitignore 并移出仓库
