# CodeMind 后端完成情况与后续任务

> 2026-10-27。本轮补齐除学生端之外的必要业务后端，本地业务库已备份并迁移验收；前端不在范围内，生产迁移和运行验收仍独立进行。

## 1. 本轮必要业务后端

| 项目 | 当前实现 | 接口与约束 |
|---|---|---|
| 01 学院与专业 | CRUD、启停、关联保护 | /api/office/departments/、majors/ |
| 02 课程与行政班 | 手动创建编辑、编码及归属保护 | /api/office/courses/、admin-classes/；保留原组织分配接口 |
| 03 账号与档案 | 普通教师学生查询维护、启停、超管重置密码 | /api/office/accounts/；教务不能管理高权限目标 |
| 04 学籍异动 | 在读/休学/毕业/退学、专业年级变更 | 非在读结束当前成员，恢复不自动回班，账号与提交留存 |
| 05 学期生命周期 | 登记、当前学期、关闭、归档 | 关闭冻结名单，归档冻结成绩，既有写接口执行状态约束 |
| 06 后台导入 | 批次、进度、结果、错误下载、安全重试 | /api/import-jobs/，默认 codemind worker 分段执行 |
| 07 审计 | 操作者、目标、前后变化、只读查询 | /api/office/audit-events/；账号、角色、组织等后台操作亦记录 |
| 08 课程组权限 | 功能权限与 CourseCollege.leader 任职 | 跨课程统一 404，教师池不等于实际任课 |
| 09 知识库与文档 | 条目 CRUD、JSON 导入、文档解析、错误及重试 | 同步文本解析，不接外部 AI、OCR 或向量库 |
| 10 章节 | CRUD、排序、知识和资料关联 | 同课程关联，全量排序事务，受引用资源先解关联 |
| 11 共享资料 | 上传、私有下载、指定班可见、教师只读 | /api/course-team/；不新增学生端或页面 |

完整字段、路径、状态与限额见 [非学生端后端接口](非学生端后端接口.md)，原教师和认证接口见 [API设计文档](API设计文档.md)。

此前完成的教师题库、作业、看板、提交代码、评语、成绩表与导出、班级私有资料、通知阅读、站内提醒和手工参考答案继续保留。学生只能完成教师布置的作业，公共题库不开放练习。

## 2. 升级前必须完成的环境动作

以下是部署验收，不能根据本地代码测试推定已完成：

1. **生产业务库升级**：本地已完成 academics 0011/0012、tasks 0004/0005、course_team 0001，原 40 张业务表数据指纹未变；生产仍需独立授权、备份、核对计划、迁移及数据验证，详见 [API设计文档](API设计文档.md) 3.10。
2. **学期配置**：旧学期迁移不推断日期，原默认当前编码 2026-2027-1 保留。教务填写正式日期并核对当前学期；未知学期须先登记再通过 API 组班。
3. **默认导入 worker**：除 long 判题 worker 外，独立常驻运行默认 codemind worker，确认 office-import-recovery 每分钟排程被实际消费。队列细节见 [异步任务设计](异步任务设计.md)。
4. **进程恢复**：验证 Web、默认 worker、long worker 及调度在重启/异常退出后能恢复，确认排队和失败任务可定位。
5. **备份恢复**：设置数据库和 private_uploads 的自动备份、保留周期及恢复流程；在隔离环境实际还原，确认文件与数据库关联一致。
6. **生产配置**：核验真实密钥、DEBUG、域名、HTTPS Cookie/CSRF、静态文件收集、日志及反向代理。设置文件中仍有开发默认值，须以部署环境实测为准。
7. **沙箱边界**：服务器内部核验 cgroup、资源与网络限制；确认 /run、/file 限源以及 5050 端口暴露。已关闭公网 /config 不代替这些检查，见 [OJ验收清单](OJ验收清单.md)。
8. **发布与回滚**：由用户推送任务分支，团队 PR 审查后统一合并；在发布前演练含数据变更的升级和恢复，数据库新增业务数据后不直接反向删表回退。
9. **真实集成与容量**：在部署环境跑教师布置→学生完成→判题→评阅→导出→关闭归档，以及后台大批次导入、撤权、worker 中断和重试。当前 SQLite 并发回归覆盖部分写路径，不能代替真实容量验证。
10. **协作 CI**：在 GitHub 上配置团队测试与检查，并核对执行结果。本轮本地提交不代表远程 CI 已执行。

## 3. 已确定与尚待确定的业务规则

- 正式学号/工号格式用户尚未确定，不能自行改成假定格式。旧 8 位自动分班仅保留兼容；正式数据优先指定行政班导入。
- 学籍变更不迁移历史作业或提交；非在读结束当前成员；恢复后须显式入班。
- 关闭与归档由教务显式操作，日期不会自动触发。关闭前须无未截止作业，归档前须无排队/判题中提交。
- 课程组全局知识和资料库持续维护，不冻结完整资料版本；归档教学班的资料可见范围保留，作业题面与成绩有独立冻结记录。
- 初始密码的校方发放方案仍可另行定稿；现有导入标记首次登录改密，重试不覆盖已有密码。

## 4. 可另行排期的增强

这些能力不属于本轮必要业务清单：

- 教师作业模板/复制、批量评阅、复杂学情报表。
- 外部 Agent 或 LLM 接入、OCR、知识向量检索与 AI 辅助评阅。
- 邮件/短信/第三方消息；当前提醒仅站内记录。
- SSO、MFA、跨域认证或统一认证平台；当前同域 Session + CSRF。
- 数据库更换与容量扩展。无需为“完整可运行”先强制更换 SQLite；切换数据库须重新验证约束和并发语义。
- 原列表接口的统一分页或 API 版本前缀迁移，须先约定兼容策略。

学生画像及其他学生自助功能、全部前端接入明确留给后续阶段。
