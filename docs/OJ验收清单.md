## 三、提交 → 判题（学生链路，真实沙箱）

| # | 步骤 | 预期 |
|---|---|---|
| 3.1 | 学生作业详情页打开题目，粘贴正确 C 代码（读两个整数输出和）提交 | ~数秒内「通过」，得分 100 |
| 3.2 | 提交错误答案代码，并尝试原样输出 stdin 或将 stdin 写入 stderr 后异常退出 | 返回「答案错误」或「运行时错误」，errorDetail 只有点号和固定说明，**不含隐藏输入、预期输出、实际 stdout/stderr** |
| 3.3 | 提交死循环代码（while(1)） | 「超时」（≤ clockLimit+余量，不拖垮队列） |
| 3.4 | 提交 Python 正确代码 | 「通过」（免编译链路） |
| 3.5 | 提交语法错误 C 代码 | 「编译错误」+ 编译 stderr（脱敏后） |
| 3.6 | 提交申请 300MB 内存的代码（基础档 256MB） | 「内存超限」 |
| 3.7 | 10 秒内连点提交 4 次 | 第 4 次 429「提交过于频繁」 |
| 3.8 | 作业截止后提交 | 400「作业已截止」（受理层拒绝，不产生排队） |
| 3.9 | 核对 go-judge 返回 time 与提交详情 timeUsed | 两者均为纳秒，不进行秒或毫秒的重复放大 |
| 3.10 | 数组请求体、错误类型 ID/语言/代码、无效查询筛选 | 400，无额外 Submission/JudgeTask，不向队列投递 |
| 3.11 | 同代码前次为 system_error 或仍排队时重新提交 | 不以该记录判 repeat，新的提交可正常进入判题 |
