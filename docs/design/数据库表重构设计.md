# CodeMind 教辅平台 · 用户、组织与历史数据模型

> 更新时间：2026-10-27。本文描述当前模型和迁移边界，替代早期 V2 目标稿。
> 本轮 `academics.0011/0012`、`tasks.0004/0005`、`course_team.0001` 已于 2026-10-27 在本地业务库备份后应用；生产环境独立验收。
> 学生端清单及教师选材下发复用既有模型，无新增表或迁移。接口见 [非学生端后端接口.md](../api/非学生端后端接口.md)、[学生端接口.md](../api/学生端接口.md)，业务约束见 [教学班级设计.md](教学班级设计.md)。

## 一、模型原则

1. 账号与学校身份分开：`User` 管登录和角色，`SchoolIdentity` 绑定学工号。
2. 学院、专业、行政班分层，成员关系保留入班和离班记录；教师任课挂教学班。
3. 课程×学院是课程组管理范围，教学班另按学期组织，课程组本身不随每个学期复制。
4. 关闭学期冻结结课名单，约束学生内容范围并保留本人历史摘要；归档冻结作业成绩，后续学籍异动不改历史快照。
5. 保留四分组与 22 个显式权限码；自动生成的 Django 模型权限不等于业务对象授权。

## 二、用户与身份

| 模型 | 主要字段 | 数据约束 |
|---|---|---|
| `users.User` | Django `AbstractUser` 字段、`name`、`must_change_password` | `username` 唯一，密码哈希保存，Group 表达角色 |
| `users.SchoolIdentity` | `user`、`school_code`、`school_number`、`identity_type`、核验状态和时间 | 同校同类型学工号唯一；同用户同校同类型唯一 |
| `users.StudentProfile` | 唯一 `identity`、`major`、`enrollment_year`、`academic_status`、创建/更新时间 | 专业 `PROTECT`；状态为在读、休学、毕业、退学 |
| `users.TeacherProfile` | 唯一 `identity`、可空 `department`、`title`、创建/更新时间 | 学院 `PROTECT`；档案学院不授予任课权限 |

封闭式导入以学号/工号创建 `username` 并绑定学校身份，不开放注册。身份默认核验状态为 `verified`；核验时间允许为空，不能把缺失时间理解为已执行另一个审核流程。

学生访问与教务学生查询使用最早的学生身份和对应档案；该身份缺档案时不自动改用另一学校的后续身份。账号管理不接受自助改用户名、学工号、角色或权限；停用保留记录。学籍变更与改密码分别走独立受控服务。

## 三、教务组织

| 模型 | 主要字段和关系 | 约束 |
|---|---|---|
| `Department` | `code`、`name`、`is_active` | 学院编码唯一 |
| `Major` | `department(PROTECT)`、`code`、`name`、`is_active` | `(department, code)` 唯一 |
| `AdminClass` | `major(PROTECT)`、`name`、可空 `enrollment_year`、允许空字符串的 `code`、`is_active` | `(major, enrollment_year, name)` 唯一；新维护接口要求入学年份 |
| `ClassMembership` | `student_profile`、`admin_class`、`joined_at`、可空 `left_at` | 同一学生最多一条当前关系；离班日期不早于入班日期 |
| `Course` | `code`、`name`、`is_active` | 课程编码唯一 |
| `CourseCollege` | `course`、`department`、可空 `leader`、`teachers`、`admin_classes` | `(course, department)` 唯一；教师池和候选行政班为 M2M |
| `TeachingClass` | `name`、`term`、`course_college(PROTECT)`、`admin_classes`、`teachers` | `(course_college, term, name)` 唯一；组成和任课为 M2M |

`ClassMembership` 的当前关系条件唯一约束 `uniq_current_student_membership` 和日期检查约束 `membership_dates_ordered` 已在迁移 `academics.0010` 实现，当前 SQLite 支持这些约束。切换数据库后必须验证目标数据库对条件约束的支持，不能假定换库自然得到相同语义。

成员记录的全部历史区间不重叠不是现有数据库约束；当日转班服务串行关闭旧关系再建新关系，防止并发产生多个当前班。历史办理日期不向普通接口开放。

组班服务与 M2M 信号保证行政班来自同学院候选池、同课程同学期不重复组班、至少保留一个组成班。成员历史、教学业务或课程组资源保护删除；不要通过中间表、批量 SQL 或直接级联删除绕过服务。

课程与行政班本轮增加 `is_active=True`。停用保留历史并阻止相应新组织、入班、组班或导入；已有关联时限制专业学院归属、行政班专业/年份等结构字段变更。归档关联基础数据的历史字段不能通过新维护接口改写，单独启停状态可维护。

## 四、学期与冻结记录

### 4.1 AcademicTerm

| 字段 | 含义 |
|---|---|
| `code` / `name` | 唯一学期编码与展示名称 |
| `start_date` / `end_date` | 学期日期；历史迁移允许同时为空，新建 API 要求同时提供 |
| `status` | `open`、`closed`、`archived`；由学期动作控制 |
| `is_current` | 至多一条为真，且当前学期必须开放 |
| `closed_at` / `archived_at` | 关闭和归档时间 |

数据库约束保证当前标志唯一、当前学期开放，以及日期同时为空或同时非空且有序。`TeachingClass.term` 保留字符串，逻辑引用 `AcademicTerm.code`，不是外键；公开组班 API 要求编码已经登记。原默认值 `2026-2027-1` 由数据迁移延续，不推断学校实际日历。

学期关闭前须无未截止作业；关闭后禁止组成、任课和普通教学写入，只允许评阅与参考答案收尾。归档须先关闭，并等待排队/判题中的提交完成。起止日期是登记信息，关闭和归档通过显式动作执行。

### 4.2 TeachingClassRecord

`teaching_class` 为唯一 `PROTECT` 关联，`roster` 保存关闭时教师名单，`gradebooks` 保存归档时逐作业成绩，另有关闭/归档时间。

关闭名单包括当时在班学生及有该教学班历史提交的离班学生。关闭后转班、毕业、改名不会重写名单；归档后成绩表与导出使用冻结结果，原始提交仍保留。学生内容读取要求当前在读在班并属于冻结名单；本人历史摘要可依冻结本人行或本人已提交的具体作业读取，归档分数取冻结本人行，不能仅凭名单恢复教学内容访问。

## 五、课程组资源

| 模型 | 主要字段与关系 | 约束与用途 |
|---|---|---|
| `CourseKnowledge` | `course_college(PROTECT)`、标题、正文、`kind`、`status`、解析错误、可见标志、私有源文件元数据 | 手工条目或文档；解析后可见正文供任课教师只读 |
| `CourseMaterial` | `course_college(PROTECT)`、标题、描述、`visibility`、私有文件元数据 | 面向本课程或指定教学班的任课教师 |
| `MaterialTeachingClass` | `material(CASCADE)`、`teaching_class(PROTECT)` | 资料与教学班唯一关联，保存指定可见范围 |
| `CourseChapter` | `course_college(PROTECT)`、标题、描述、正数 `position`、可见标志、知识和资料 M2M | 同课程×学院内顺序唯一；关联资源必须属于同一范围 |

课程组负责人关系决定管理范围，资源归属不等于整个课程组分组均可写。教师只读依实际任课关系过滤；学生不直接读取源库。教师从资料或章节选材下发时，核验目标任课班、学期和源资料范围，复制为独立 `TeachingMaterial`，不新增源库外键；源资料替换或删除不改变班级副本。知识和资料有关联章节时须先解除关联再删除。涉及归档教学班的指定资料可见范围不能改写或删除；共享资源正文/元数据继续按课程组规则维护，与冻结作业成绩分开。

## 六、导入批次与审计

### 6.1 OfficeImportJob

新增教务后台批次独立于既有 `AsyncTask`。主要字段为导入类型、提交人、可选目标行政班/课程×学院、状态、总量/完成量/成功量/失败量、物理行游标、错误列表、执行轮次、过期时间与起止时间。

状态为 `pending`、`running`、`succeeded`、`partial`、`failed`。提交人及目标外键使用 `SET_NULL` 保留批次；运行时重新校验提交人和目标。源文件随机标识只在服务内部使用，接口不返回物理路径或初始密码。每行业务和游标同事务，分段续投保留轮次；人工重试重新上传，不覆盖已有账号姓名或密码。

终态删除含初始密码的原始表格；超时和孤立文件由恢复任务清理。`tasks.0005` 在默认 `codemind` 集群注册每分钟恢复排程。详细状态和进程配置见 [异步任务设计.md](异步任务设计.md)。

### 6.2 AuditEvent

字段包含操作人 `actor(SET_NULL)`、用户名快照、动作、对象类型/编号、选定的变更前后 JSON 和时间，按动作/时间及对象建立索引。

业务审计与业务写入同事务；失败回滚不会留下成功变更事件。Django 后台角色、账号、组织操作也记录业务审计，同时保留原生 `LogEntry`。字段明确挑选并过滤密码、令牌、文件正文、判题数据等敏感内容，不保存请求原文。查询接口只读；删除操作人后保留用户名与对象快照。

## 七、迁移边界

| 阶段 | 当前代码与数据迁移 |
|---|---|
| 已有 V2 重构 | `College → Department`、`Clazz → AdminClass`；身份、资料、专业、成员关系、教学班已落地，不再作为未实施目标 |
| 已有约束 | `academics.0010` 加当前成员唯一与日期检查；`users.0018` 收回旧课程组公共题库权限 |

2026-10-27 经用户单独授权，本地业务库已应用本轮 5 项迁移，备份为 `db.sqlite3.backup-20261027-150652-227043`。原有 40 张业务表按原列计算的逐行指纹未变，课程/行政班新增启用值均为 true；新增 10 张表，其中学期表登记 1 条，其余 9 表为空。完整性、外键和权限一致性检查通过。生产环境仍须独立备份、迁移和验收，不能用本地结果替代。

## 八、仍待学校确认

正式学号/工号格式、学校组织编码、课程编号和实际学期日历尚未定稿。现有 8 位自动分班规则是 `YYYY + 专业码 + 班序`，没有学生个人序号，不应当作正式学号制度。格式未定时使用指定行政班导入，不改写已有登录账号或学工号。
