# CodeMind 教辅平台 · 用户权限设计

> 文档性质：正式设计说明
> 更新时间：2026-10-27
> 范围：当前权限码、对象范围和后端业务约束；本轮不新增前端或学生自助功能。
> 部署状态：本轮新迁移已于 2026-10-27 在本地业务库备份后应用，22 个显式权限及角色关联不变；生产环境独立验收。

## 一、设计目标

1. **安全性第一**：服务端强制校验，前端隐藏按钮只影响体验、不作防线
2. **前后端分离**：权限以 API 返回的权限码列表为准，前端据此渲染界面
3. **细粒度可控**：每个功能点一个权限码，可在 /admin/ 后台直接勾选调整
4. **最小权限原则**：各角色只拥有完成本职所需的权限，教师权限进一步限定到教学班级

## 二、角色体系

采用「超级用户 + 四个分组」结构。角色不设字段，直接使用 Django 原生 Group。

| 角色 | 分组（Group） | 说明 | 账号来源 |
|---|---|---|---|
| 系统管理员 | —（superuser） | 不参与分组，拥有全部权限，管 /admin/ 后台 | createsuperuser |
| 教务 | 教务 | 管理全校班级、课程、教师分配、组长指定 | **仅由管理员在 /admin/ 添加并勾选「教务」分组** |
| 课程组 | 课程组 | AI Agent知识库、班级资料、课程章节设计 | **不开放导入**，教务设课程组组长时自动加入分组 |
| 教师 | 教师 | 班级通知、学情、资料、作业等（仅限教学班级） | 教务工作台 xlsx 批量导入 / 工号添加 |
| 学生 | 学生 | 作业查看与提交 | 教务 xlsx 导入，可指定行政班；旧学号自动分班规则保留为占位 |

要点：
- 登录账号统一：学生用学号、教师/教务用工号，`username` 数据库唯一约束防撞号
- 无注册界面：所有账号由系统统一创建
- 课程组组长同时也是教师（两组共存），撤组长时间不再担任任何组长时自动移出课程组

## 四、权限模型与校验机制

### 4.1 技术实现

- 自定义用户模型 `User(AbstractUser)`（users/models.py），角色 = Django 原生 Group，不加 role 字段
- 权限点注册在 `User.Meta.permissions` → Django 原生 Permission（post_migrate 自动入库）
- 权限码 → codename 映射在 `users/permissions.py::PERM_CODES`（如 `'class:manage' → 'class_manage'`）
- 四分组及其权限分配由数据迁移创建（users/migrations/）

### 4.2 核心工具（users/permissions.py）

| 工具 | 用途 |
|---|---|
| `hasPerm(user, code)` | 判断用户是否拥有权限码；**超级用户直接放行**；未知权限码返回 False（fail-closed） |
| `getGroupKey(user)` | 返回分组 key（superuser/admin/course_team/teacher/student）；按 `GROUP_PRIORITY` 显式优先级匹配（组长同时是教师时返回课程组） |
| `requirePerm(code)` | **页面**视图装饰器：未登录跳登录页，无权限返回 403 |
| `PermRequired` | **API**（DRF）权限类：视图类声明 `permCode` 即自动校验，无权限返回 403 |
| `IsTeacherGroup` | **API**（DRF）权限类：仅教师组（或超级用户）可访问教师工作台 API |
| `IsStudentGroup` | **API**（DRF）权限类：仅学生组（或超级用户）可访问学生工作台 API |
| `IsCourseTeamGroup` | **API**（DRF）权限类：仅课程组（或超级用户）可访问课程组 API |
| `IsSuperUser` | **API**（DRF）权限类：仅系统管理员（is_superuser）可访问，用于题库导入/维护 |

页面入口一律服务端强制：教务页面逐页 `requirePerm`（导入=class:manage、课程页=course:manage、班级页=class:manage），教师页面 `requireTeacherGroup`。

### 4.3 教学业务对象级工具（teaching/helpers.py）

| 工具 | 用途 |
|---|---|
| `getTeacherTeachingClass(user, tcId)` | **对象级校验**：教学班教师表必须含当前用户，否则 404（见第五节） |
| `getStudentTeachingClass(user, tcId)` | **对象级校验**：经"学生→行政班→教学班"三跳推导出教学班后校验，否则 404（学生端 API 用） |
| `requireTeacherGroup` | 教师工作台页面入口：仅教师组（或超级用户）可访问 |
| `requireStudentGroup` | 学生工作台页面入口：仅学生组（或超级用户）可访问 |

对象级回归位于 `teaching/tests*.py`、`academics/tests*.py`、`course_team/tests*.py` 与相关用户测试中，覆盖任教/在班/跨课程/不存在/超级用户、学期状态及文件下载。测试数量随代码变化，以交付时实际结果为准。

### 4.4 权限信息接口

- `GET /api/auth/me/`：返回当前用户 `groupKey`、`groupName`、`permCodes`（拥有的全部权限码）
- 前端登录后调它渲染界面；**后端校验才是防线**

### 4.5 质量保障

- **权限一致性系统检查**（users/checks.py）：`manage.py check` 自动断言四处定义一致——Meta.permissions 注册 ↔ PERM_CODES 映射 ↔ GROUP_PERMISSIONS 分配 ↔ 数据库各分组实际权限。管理员在 /admin/ 配错分组时能立即发现
- **权限回归**（`users/tests*.py`）：角色入口、权限声明、后台防提权、账号维护及重置密码边界。
- **业务回归**：教学对象范围、课程组负责人范围、学期关闭/归档、学籍与导入事务、审计及文件生命周期；部署还须验证实际队列和沙箱。

## 五、两级权限模型（核心设计）

分组权限码只回答「**能不能用这个功能**」，对象级校验回答「**能不能对这个对象用**」。

| 层级 | 载体 | 示例 |
|---|---|---|
| 功能级 | 分组权限码（Group → Permission） | 教师有 `notice:manage` → 能用通知功能 |
| 对象级 | 业务接口内校验 | 该教学班的 `teachingClass.teachers` 含当前教师 → 能对这个班发通知 |

教师功能接口的标准写法：

```
1. 入口校验：登录（IsAuthenticated）+ 分组权限码（PermRequired）
2. 对象校验：getTeacherTeachingClass(user, teachingClassId) —— 非本班教师一律 404
```

404 而非 403 是刻意设计：**不暴露班级是否存在**，防止外人探测。

其他对象级约束：
- 教务班级详情必须从课程×学院进入（URL 自带课程上下文，跨课程 404）
- 教师分配候选只显示该课程×学院教师池内的教师
- 课程教师池导入同时要求 `class:manage` 和 `class:assign_teacher`；普通教师账号导入仍只要求 `class:manage`，避免通过导入动作绕过任课分配权限。

## 六、权限分配方式

| 角色 | 谁操作 | 方式 | 生效 |
|---|---|---|---|
| 教务 | 系统管理员 | /admin/ 创建用户 + 勾选「教务」分组 | 立即 |
| 教师 | 教务 | 工作台 xlsx 导入 / 班级详情工号添加 | 立即（导入自动入「教师」组） |
| 学生 | 教务 | XLSX 指定行政班导入，或使用旧规则自动分班 | 立即（自动入「学生」组） |
| 课程组 | 教务 | 课程×学院页设课程组组长 | 设组长自动入组，撤销且不再任组长自动移出 |

原则：**权限随分组自动生效，不逐人配置**；谁有教务权限完全由管理员掌控。

## 七、关键约束与业务规则

1. **教师权限仅限教学班级**（对象级校验，不可绕过）。教师可同时执教多个班级，**所有权限的边界 = 其执教班级集合**。个人题库也不例外：题目归教师本人管理，但只能应用于自己执教的班级（发布作业选班级时校验）。公共题库由系统管理员统一导入/维护，教师只读、可选题，不能修改
2. 作业已有提交后不能删除；题目列表在已有提交后锁定。答案首次公开后不能延期或换题；关闭学期只允许评阅和答案收尾，归档后教学数据只读。
3. **教师无权修改课程组资料**（课程组资料由课程组管理）
4. **教务账号不参与批量导入**，仅管理员在 /admin/ 添加
5. **班级详情必须从课程入口进入**（课程 → 学院 → 班级，跨课程 404）
6. **超级用户不参与分组**，拥有全部权限，仅作后台管理
7. 登录防暴力破解：django-axes 连续失败 5 次锁定 1 小时

### 9.2 通知、提醒与参考答案权限边界

- `notice:manage`：仅任教教师可管理本教学班通知和查看阅读统计；同班教师共同维护。开放学期按当前名单统计，关闭后教师历史统计使用冻结名单。学生仍以当前在班关系读取和标记本人已读，不能替别人记录。
- 通知编辑保留首次阅读时间；已读表示曾打开通知，不保证已读最新版本。首次阅读唯一约束为 `(notice, user)`，重复标记不刷新首次阅读时间。
- `homework:remind`：仅任教教师可在作业开始至截止期间向尚未交齐题目的当前学生生成站内提醒。完成提交按每道题是否有提交记录判断，系统错误也算已提交，不以是否 AC 或得分判断。同一作业、同一学生滚动一小时内只提醒一次，不同教师共享冷却。
- 学生以 `notice:view` 读取和标记本人的站内提醒，访问时仍须当前在班。接收人由服务端计算，发送教师取当前会话；不接受任意指定接收人或发送人，不发送邮件、短信或外部消息。
- `homework:answer`：仅任教教师可维护本作业各题的手写参考答案，并在 `now > deadline` 后手动公开；至少存在一条答案，可部分公开。学生以 `homework:view` 查看当前班级、已经公开且已经截止的答案；提前、跨班或离班访问均返回 404。
- 参考答案独立于判题数据，接口不读取或发布隐藏测试点、SPJ、判题快照或 Agent 自测代码。公开后可修订或删除答案，但首次公开标志永久保留，此后不得延长截止时间或更换题目。
- 以上接口复用现有 22 个权限码，不改变角色分组；功能权限不足返回 403，跨班对象与不存在对象返回相同 404。

### 9.3 教务账号、学籍与组织管理

- 学生列表、详情、成员历史、转班、退班和独立学籍维护复用 `class:manage`，身份和办理日期由服务端确定。普通转退班不能夹带学籍字段；学籍接口显式接受状态、专业、入学年份和可选新班，不接受改登录账号、学号或角色。
- 普通转班仅限同专业、同入学年份，目标专业与学院须启用；转退班按本地当日生效，重复操作幂等。账号、历史成员关系和原作业提交保留，学生教学数据访问按当前成员关系即时改变。
- 行政班存在当前或历史成员时禁止硬删除；仍组成教学班时也须先显式调整组织。有作业、资料或通知的教学班不能解散，其课程×学院也不能解除，失败统一返回业务错误并完整回滚。
- 教学班正向、反向移除或清空组成关系均受至少一个组成班约束；已用于组班的行政班不能移出候选池。服务及 M2M 信号共用课程事务锁保护检查与写入。
- 休学、毕业、退学结束当前成员关系；恢复在读不自动回班。跨专业/年份变更结束原关系，指定新班时须匹配新专业、年份和启用状态；账号与历史提交保留。
- 教务账号接口只管理普通教师和学生；`is_staff`、超级用户、教务/课程组成员、含直接权限或超出普通教师/学生权限集合的目标，不向普通教务开放。目标不可管理与不存在统一返回 404。
- 他人密码重置仅系统管理员可操作，使用 Django 密码策略并置首次改密标志；旧会话失效。账号接口不接受角色、权限、学工号、用户名或密码哈希，不提供硬删除账号动作。
- Django 原生用户、组、身份及学生/教师档案管理仅系统管理员可用。后台学籍修改复用受控学籍服务；教务使用业务 API 管理普通目标。
- 本轮保持 22 个显式权限码及角色分组，新增业务模型迁移已在本地应用并校验，见 [数据库表重构设计.md](数据库表重构设计.md)。元数据新增 8 个 content type 与 32 个原生模型权限，已有权限记录和角色关联未变；正式学号格式仍待确认。

### 9.4 学期、课程组与审计

- 学期管理使用 `course:manage`。学期关闭前须无未截止作业，关闭后冻结名单并允许评阅/参考答案收尾；归档前须无排队或判题中的提交，归档后冻结成绩、保留任课教师历史读取权限，不允许教学写入。
- 课程组知识、资料和章节的管理同时要求对应功能权限与负责人任职。仅持有课程组分组或其他课程的组长身份不能跨课程写入。
- 课程组教师只读接口要求教师入口资格及实际任课关系；知识只读已解析且可见内容，资料依据课程或指定教学班范围过滤，章节裁掉不可见资源关联。学生不新增此类接口。
- 共享库资源可继续复用；涉及归档教学班的指定资料可见范围不能改写或删除，资料正文和元数据仍按课程组资源规则维护，不是作业或成绩快照的一部分。
- 后台导入入口使用 `class:manage`；课程导入再查 `course:manage`，课程教师导入再查 `class:assign_teacher`。批次只对提交人或超级用户可见，执行中逐行重查权限，撤权或停用后停止后续行；重试不覆盖已有账号密码。
- 审计查询使用 `class:manage`，只读且支持操作人、动作、对象及时间筛选。受控服务、既有组织 API、后台角色/账号/组织维护均记录选定前后字段；密码及其哈希、文件正文、隐藏测试点和请求原文不入审计。业务回滚时审计一并回滚。
- 新接口完整契约见 [非学生端后端接口.md](非学生端后端接口.md)。
